## 当前产品与工程事实

Apple 已正式发布 iPhone Duo。官方规格列出 7.6 英寸内屏、5.4 英寸外屏；不能用面板像素直接推断 App 可用点数、布局断点或安全区。[产品页](https://www.apple.com/iphone-duo/)、[技术规格](https://www.apple.com/iphone-duo/specs/)。原 BACKLOG 中 Duo 指折叠屏的解释继续有效，但现按正式产品资料评估。

当前 Debug／Release 均为 `TARGETED_DEVICE_FAMILY = 1`、iPhone 竖屏、最低 iOS 16（`BaseballMaster.xcodeproj/project.pbxproj:491–529`）。因此 iPad 尚未启用原生通用 App 布局；可以研究 iPhone 兼容运行，但不能宣称完成 iPad 适配。

本机工具为 Xcode 26.1.1／iOS 26.1 SDK，已安装 iOS 26.2 模拟器运行时，没有 Duo／iOS 27.1 的测试环境。Apple 开发说明区分三种构建效果：SDK 26 及以前可运行，展开后居中留白；SDK 27 扩大内容范围；SDK 27.1 进一步使用完整显示区并引入竖排栏位。后续正式 Duo 验收需要对应工具链和模拟器，不能用 iPhone 17 模拟器替代。[Apple 适配说明](https://developer.apple.com/iphone-duo/prepare/)。

## 主要工作面

| 工作面 | 当前代码与风险 | 建议验收 |
| --- | --- | --- |
| 工程与方向 | 仅 iPhone、竖屏；原生 iPad 需要调整设备族及方向配置 | 同一 Bundle ID 覆盖升级，iPhone 行为保留，iPad 横竖屏可用 |
| 导航与记分 | `MainViews.swift:7` 为 TabView＋各页 NavigationStack；`ScorekeepingViews.swift:33` 只有按可用宽高隐藏／显示球场的窄屏布局 | 宽屏可将球场与操作区并列；窄窗口退回单列；记录入口和草稿不丢 |
| 球场与击球图 | `Components.swift:333,384` 默认固定高度，慢垒最低 330；`BattedBall.swift:183` 图高 265 | 合理限制球场比例和列宽；点选逆映射仍正确；旧坐标保持不变 |
| 开屏 | `ConfigurableLaunchScreen.swift:251–271` 已用局部 GeometryReader，但 Logo、底部图标和两行文案位置偏向竖屏构图 | 短宽窗口无重叠，内外屏切换不重复开屏，安全区内跳过可点 |
| Sheet／确认 | Pro、跑者处理、阵容、完赛去向均含临时选择状态；Duo 有侧栏和折叠避让行为 | 选到一半旋转／缩放／折叠，选择与返回路径保留；取消不记球、确认只记一次 |
| 分享／导出 | `ResultsViews.swift:648`、`LiveBroadcastViews.swift:112` 包装 UIActivityViewController | 原生 iPad popover／sheet 实测定位、取消、分享和返回；目前没有锚点本身不能证明必崩溃 |
| 窗口与存储 | `BaseballMasterApp.swift:16,56–83` 共用 GameStore／WindowGroup 与前后台处理，生成配置支持多场景 | 首版明确是否支持同 App 多窗口；若支持，确保窗口切换不覆盖草稿、不重复上传，后台备份与直播正确 |
| 无障碍与发布 | 尚无大屏完整证据及对应商店材料 | 长队名、大字体、深色、键盘遮挡、VoiceOver 和新设备截图独立验收 |

本轮搜索未发现生产 Swift 中使用 `UIScreen.main` 或按 `.phone/.pad` 区分布局的明显模式；已有 GeometryReader 与统一坐标映射可复用，但不等于布局已适配。优先根据可用空间、size class 和安全区安排内容，不用机型名或物理朝向决定布局。

Duo 的内外屏、竖向栏位、系统 sheet 和半折叠交互需要单独检查。优先使用系统导航／弹层并保持内外屏同一功能层级；球场这种自绘交互区需检查折叠区域的可点位置。来源：[Apple Duo 设计讲解](https://developer.apple.com/videos/play/tech-talks/111466/)。

## 分期建议

以下为代码审阅后的初步工程估算，单位为人日，非交付承诺；环境安装、真机取得和审核等待另计。共享的宽窄布局只做一套，不能把 iPad 和 Duo 简单当两个独立 App 重写。

| 阶段 | 内容 | 初估 |
| --- | --- | --- |
| A：3.1.1 基础兼容确认 | 保持现有设备族，完成 iPad 兼容模式和 Duo 旧 SDK 行为检查；补必要阻断修复 | 1–2 人日；Duo 验收受环境约束 |
| B：通用布局 | 启用 iPad；记分双列、导航、阵容／统计、球场、弹层、开屏与导出适配 | 5–8 人日 |
| C：Duo 原生适配 | 新工具链构建，内外屏／尺寸变化、侧栏、安全区与半折叠检查，复用 B 的布局 | 2–4 人日 |
| D：完整回归与发布材料 | 数据／UI／升级／后台／导出回归及设备截图 | 2–3 人日 |

完整原生适配合计约 **10–17 人日**（含 A），为主代理计入页面完善和完整回归后的保守估算；仅做基础共用布局的初估更低。独立多窗口同时记不同比赛另估 2–4 人日，不包含在此数内。有数据状态或新 SDK 迁移问题时重新估算。建议 3.1.1 先结清本版缺陷和原发布待办；原生 iPad＋Duo 作为单独适配范围安排，版本仍待用户决定。
