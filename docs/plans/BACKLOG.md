#### 首版展示方案

用户已明确的是“桌面小组件显示后续比赛预告”。以下尺寸、场数和交互为首版产品建议，沿用当前 iPhone App 的支持范围与 iOS 16 最低版本：

| 项目 | 首版方案 |
| --- | --- |
| 添加方式 | 用户从 iPhone 主屏幕的小组件选择器添加“比赛预告” |
| 小号 | 最近一场比赛，突出对阵双方、开赛日期和时间 |
| 中号 | 按时间展示最近 3 场，逐场显示双方与开赛时间 |
| 大号 | 按时间展示最近 5 场，有空间时补充已确认的比赛模式 |
| 数据来源 | 本机 App 已保存的未来比赛，涵盖本队比赛和观赛；普通棒球、教练投手、成人慢垒共用入口 |
| 点击 | 进入对应比赛的赛前准备；空状态点击进入安排比赛入口 |
| 无赛程 | 显示“暂无后续比赛”和“打开 App 安排比赛”，不展示演示赛事 |
| 外观 | 沿用 [已确认品牌](../brand/BRAND.md) 与现有 App 图标，适配浅色、深色及支持该能力的系统版本上的着色显示 |

比赛数量少于尺寸上限时显示实际数量，不填充虚假行。中、大号按行提供对应比赛入口，小号整块进入最近一场。长队名优先使用现有球队简称，详情及无障碍标签保留完整队名。

#### 赛程与更新时间

从 `StoredGame` 的已保存数据生成展示列表：状态为 `.scheduled`、具有有效的 `scheduledAt`，且开赛时间不早于当前时刻；按开赛时间升序排列，同一时刻采用稳定顺序。已进行、已结束、已删除以及过时的安排不再列为后续预告。缺少安排时间的旧数据不以创建日期冒充开赛时间。

计划时间已过但尚未开始的比赛，仅从预告列表移出，比赛本身仍由 App 保存并供用户处理。改期后重新进入列表；小组件不会因时间到达而启动记分。

App 在赛程新增、编辑、改期、删除、开赛或恢复备份成功后，重新生成共享赛程摘要并请求刷新。时间线在开赛时间和日期边界准备下一批内容，使 App 未打开时也可展示后续安排。系统决定实际刷新时机，验收区分“摘要与时间线内容已正确更新”和“桌面已显示新版内容”，不承诺秒级刷新。[Apple 时间线与刷新说明](https://developer.apple.com/documentation/widgetkit/keeping-a-widget-up-to-date)

日期与时间使用系统时区和语言设置，跨日及跨年显示明确；时区变化后仍与 App 中同一场比赛的时间一致。未来比赛尚未完成规则设置时，只展示已保存的对阵和开赛时间，不将默认规则当作已确认信息。

#### 数据共享与点击入口

首版拟新增 WidgetKit 扩展，并为 App 和扩展配置同一个 App Group。主 App 成功保存数据后，将精简赛程摘要原子写入共享容器；扩展只读取摘要，避免由小组件加载完整记分 Store 或执行数据库迁移。App Group 是主 App 与扩展共享容器的系统能力。[Apple App Groups 配置说明](https://developer.apple.com/documentation/xcode/configuring-app-groups)

摘要只包含稳定比赛 ID、主客队名称及简称、安排时间、必要的模式说明和生成时间，不携带完整球员名单、逐球记录或直播发布凭证。摘要作为可重建缓存，不替代正式数据库；启动、升级和备份恢复后从正式数据重新生成。缺失、读取失败或格式不支持时显示“打开 App 更新赛程”，不显示错误的演示内容。

点击通过比赛 ID 跳转，主 App 初始化完成后重新查询当前状态。尚未开赛进入赛前准备，已经进行或结束进入对应比赛页面，已删除则提示并返回比赛列表；均不自动开始记录。WidgetKit 支持通过 `widgetURL` 和适用尺寸的 `Link` 将点击交给主 App。[Apple 小组件与跳转说明](https://developer.apple.com/documentation/widgetkit/creating-a-widget-extension)

当前工程核查：已有 `StoredGame.scheduledAt`、`.scheduled` 与 `GameStore.scheduledGames`；工程目前只有 App 和测试 Target，没有小组件 Target 或 App Group 配置。宣传海报中的场地和备注仅用于海报编辑，没有保存在比赛数据中；首版预告使用已有对阵及时间字段，场地展示待具备持久化字段后再扩展。

#### 验收场景

| 编号 | 场景 | 完成标准 |
| --- | --- | --- |
| WA01 | 0、1、多场未来比赛，小／中／大号 | 场数、排序、主客队与时间正确；没有比赛时显示明确空状态，超过上限显示最近场次 |
| WA02 | 本队比赛、观赛、普通棒球／教练投手／慢垒、未完成规则设置 | 合法未来赛程均可展示，不遗漏观赛，不编造尚未确认的模式或规则 |
| WA03 | 新增、改期、删除、正式开赛、球队更名 | 成功保存后共享摘要对应更新并请求刷新，下一次系统加载不显示已删除或已开赛比赛 |
| WA04 | 同一时刻多场、跨日／跨年、时区变化、安排时间已过 | 排序稳定、时间与 App 一致，后续时间线移出过时比赛并补入下一场；不会自动开赛 |
| WA05 | 点击单场、点击多场中的某行、冷／热启动、赛程已改变 | 进入正确比赛的最新页面；已删除时提示并回到列表，空状态进入安排入口，不误开赛 |
| WA06 | 杀进程、设备重启、覆盖升级、备份恢复及缓存缺失／损坏 | 摘要可重建、不会混入旧库赛程；缓存不可用有明确状态，不影响正式数据库 |
| WA07 | 长中文／英文队名、深色、系统着色、三种尺寸和无障碍 | 时间与对阵可读，无裁切重叠；无障碍朗读完整比赛信息，品牌样式沿用基准 |
| WA08 | 真机添加、移除后重加、App 与扩展签名归档 | 小组件选择器可找到“比赛预告”，可正常放置并更新；归档包含可运行扩展，检查结果有证据 |
