## 这次更新是什么

3.0 的重点是：**同一支球队，可以由不同记录员记录比赛，也可以让受邀成员查看历史比赛和年度统计。**

共享从「球队」进入，无需注册账号。球队、名单、比赛、权限和恢复由 `baseballmaster.cc` 的自有服务处理，不使用 iCloud／CloudKit 或 Apple 账号。仍可只在本机记分，不必开启共享。

保留「比赛／球队／统计／我的」四栏导航和熟悉的记分页面。2026-10-13 用户确认击球类型、方向落点图与常用局面改版正式纳入 [3.1](3.1-BATTED-BALL.md)，不加入本次 3.0 交付。

## 本版功能范围

| 功能 | 3.0 已完成的内容 |
| --- | --- |
| 球队共享 | 创建共享球队或通过邀请加入；球队使用独立编号，同名不自动合并；共享与纯本机使用并存 |
| 固定三种角色 | 管理员、记录员、普通成员，不需要逐项设置复杂权限；每队最多两名管理员 |
| 球员资料同步 | 管理员和记录员都可新增、修改球员姓名和背号，其他设备联网后获取；同名或同背号不自动当成同一人 |
| 比赛同步 | 同步规则、双方阵容、比赛时间、逐球记录、比分和正式统计；不同记录员可分别负责不同比赛 |
| 记录交接 | 同一场由一台设备记分；普通交接先同步，再由双方核对确认，断线不会自动换人 |
| 冲突与失联处理 | 未同步的本机记录保留；管理员可核对草稿、处理失联接管；旧设备不能覆盖新正式记录 |
| 队内查看 | 记录员和普通成员可查看全队已共享比赛及统计；网页是否开放不影响队内 App 查看 |
| 历史网页观看 | 永久开放、仅指定人员或不开放；关闭观看保留数据，指定观看者可逐人撤销 |
| 设备配对与管理恢复 | 新旧设备核对短语后接入；可移除设备，管理设备丢失时使用提前保存的恢复卡 |
| 按年度统计 | 不主动创建或划分赛季，按实际比赛日期归入年度；跨年更正后列表和统计同步调整 |
| 历史比赛导入 | 管理员将本机已结束比赛导入共享球队，先预览重复记录和球员对应；先备份，原本机比赛保留 |
| 历史球员对应 | 管理员可核对当场球员与正式名单的对应关系，支持改选和解除；历史快照不按同名自动改写 |
| 比赛时间补填 | 开始比赛时可选择今天以前的日期与时间；已结束比赛可更正时间，实际计时独立 |
| 阵容选人显示背号 | 双方阵容确认时，候选项同时显示姓名和背号，保留 0／00 和多背号 |
| 练习页面与换投确认 | 修复练习球场裁切；换投先核对真实投手，取消不留下换投记录，覆盖守备换人、调整守位和阵容编辑 |
| 记分文案 | 使用「坏球／好球 - 看／好球 - 挥空／界外」，同步用于新产生的直播和文字记录；不追改旧内容 |
| 完整档案与服务维护 | 管理员导出全队档案，校验后可导入为本机只读资料；服务有持久存储、加密备份、恢复、监测和容量限制 |

## 已确认的关键规则

### 管理员、记录员和成员

| 操作 | 管理员 | 记录员 | 普通成员 |
| --- | --- | --- | --- |
| 查看全队业务资料、比赛与统计 | 可以 | 可以 | 可以，只读 |
| 新增、修改球员姓名和背号 | 可以 | 可以 | 不可以 |
| 修改球队资料、停用或恢复球员 | 可以 | 不可以 | 不可以 |
| 邀请成员、调整角色、移除其他成员、解散球队 | 可以 | 不可以 | 不可以 |
| 记录比赛、赛后更正 | 持有当前记分权时可编辑 | 负责或正式接手，且持有当前记分权时可编辑 | 不可以 |
| 设置历史观看方式、授权观看者 | 全队比赛 | 自己负责的比赛 | 不可以 |
| 导入历史、核对历史球员对应、导出全队完整档案 | 可以 | 不可以 | 不可以 |

每队最多 **两名有效管理员**，按成员身份计数，同一个人的多台配对设备不重复占名额。在「共享球队 → 成员管理」将已加入的成员或记录员设为管理员；已有两名时先调整其中一位的角色，再设置新的管理员。最后一名管理员不能直接降级或退出。

### 实时直播与历史回看

- 有效实时直播链接继续持链接可看，沿用原来的开播、关闭和到期方式；终场后原链接仍有效的时间内也按原规则观看。
- 原直播链接关闭或到期后，留存内容通过独立历史入口观看，使用新权限，不自动从失效直播链接放出历史。
- 历史「永久开放」允许持链接观看；「仅指定人员」需要核对授权，普通转发不能获得权限；「不开放」关闭历史网页访问，但保留完整记录和队内 App 查看。

### 投手局数的两种口径

赛事的 **登板局数限制** 与统计中的 **投球局数 IP** 分别计算。有限制的比赛中，投手确认登板，即使还没投球也占本局的登板额度；同一投手同一局不重复占用。统计 IP 仍按实际取得的出局数累计，新投手从 0.0 开始。

因此换投必须核对姓名和背号后确认。尚未确认的候选选择不算实际换投，取消不留下换投记录或误占额度。

## 常用操作入口

1. **开始共享**：「球队 → 球队共享 → 新建共享球队／通过邀请加入」。未安装 App 的邀请接收者可在网页看到 iOS 下载入口。
2. **新增或修改球员**：「共享球队 → 添加球员」，或打开已有球员的菜单选择「编辑资料」。管理员和记录员都可操作。
3. **设置第二名管理员**：「共享球队 → 成员管理 → 对应成员 → 设为管理员」。
4. **交接记录**：「共享球队 → 球队比赛与历史 → 对应比赛 → 交接」，由双方核对确认后接手。
5. **设置历史观看**：「对应比赛 → 历史网页观看」，选择开放方式并按需核对观看者。
6. **导入本机旧比赛**：「球队比赛与历史 → 导入历史比赛」，先预览、核对、备份，再上传。
7. **换设备或恢复管理权**：从「球队共享」进入设备接入或恢复入口；恢复卡应提前保存。

## 存储与速度

完整合成比赛样本测量：每场正文及网页投影约 0.82–0.85 MB；每队每月 20 场约 **17 MB**。加上索引、审计和草稿，可先按每月 **25–50 MB** 留余量，备份另算。不是照片或视频存储预算，也不是所有比赛的固定大小。

样本完整上传确认中位数约 224 ms、P95 约 631 ms；30 并发历史读取 P95 约 1.48 秒。当前文字与比赛同步可用，不能据此承诺所有网络和地区的速度。详细样本与限制见 [容量及速度测量](../releases/3.0/CAPACITY.md)；套餐账单与真实 30 天增长仍属于运行期事项。
