## 1. 打开项目并设置账号

用 Xcode 打开仓库根目录的 `BaseballMaster.xcodeproj`。

1. `Xcode → Settings → Apple Accounts → Add Apple Account`，登录原 App 的开发者账号。
2. 左侧点蓝色工程图标，选择 `TARGETS → BaseballMaster`。
3. 在 `Signing & Capabilities` 勾选 `Automatically manage signing`，Team 选择原 App 团队。保留 Bundle ID。
4. `General → Identity` 核对 Version **2.0** 和 Build。Build 当前为 **1**；同版本下已用过 1 时，使用下一个未用构建号，例如 2。后续重传修改过的包也递增 Build。

本机 Xcode 26.1.1 / iOS 26.1 SDK 满足当前 Apple 要求的 Xcode 26 与 iOS 26 SDK 最低版本；以实际上传校验为准。[Apple SDK 最低要求](https://developer.apple.com/news/upcoming-requirements/?id=04282026a)

在 App Store Connect 中沿用已有 App 记录，新建 iOS 版本 **2.0**，不另外创建同名 App。Apple 要求正式版本号递增；实际上传报错已经确认此前批准版本为 1.5，原 1.1.1 不能继续上传。App Store Connect 的版本与工程 Version、归档内的 CFBundleShortVersionString 统一为 2.0。[Apple 创建新版本说明](https://developer.apple.com/help/app-store-connect/update-your-app/create-a-new-version/)

## 2. 上传前在自己的手机确认一次

保留旧 App，先导出完整备份。连接手机，在 Xcode 选择该手机运行并覆盖安装；不要卸载旧 App 来代替升级检查。若签名或安装报错，保留旧数据并记录错误，不清空资料。

确认旧名单、已结束比赛、进行中比分／垒况及统计仍在；续记一球、退出重开后记录仍在。另建测试比赛，检查选定先发投手、双方阵容更改、A → B → A 再上场、两好球触击界外、三出局换边、投手提示和撤销／重做。最后预览一次 PDF 报告。这些真机步骤目前尚未完成。

## 3. 重新归档并上传

1. Xcode 顶部 Scheme 选 `BaseballMaster`，设备选 `Any iOS Device (arm64)`，不要选模拟器。
2. 点击 `Product → Archive`，完成后打开 `Window → Organizer → Archives`。
3. 选择本次新生成的归档，核对 **2.0（本次 Build）**。必须使用新生成的 **2.0（1）**，不要重选旧 `1.5`、`1.6` 或失败的 `1.1.1（1）` 归档。修改工程不会改变已生成的归档。
4. 点击 `Distribute App → App Store Connect → Upload`；按页面完成自动签名、校验与上传。若提示缺分发证书，使用已登录的原团队账号处理签名。
5. 保留上传完成结果和本次归档，随后在 Connect 等待构建处理完成。这里选择 App Store Connect 上传即可，不选择仅供 TestFlight 内部测试的分发方式，也无需添加测试组。

操作依据：[Apple 的 Xcode 上传步骤](https://help.apple.com/xcode/mac/current/en.lproj/dev442d7f2ca.html)。上传后需要经过 Apple 的构建处理才会可选：[上传与构建处理](https://developer.apple.com/help/app-store-connect/manage-builds/upload-builds)。

## 4. 填写 2.0 正式版本页面

进入 [App Store Connect](https://appstoreconnect.apple.com/) → Apps → 棒球比赛记录大师 → 分发 / App Store → iOS **2.0**。

| 页面字段 | 填写内容 |
| --- | --- |
| 构建版本 / Build | 选择这次上传的 **2.0（本次 Build）** |
| 此版本的新增功能 / What's New | 粘贴同目录 `01-版本更新说明.txt` 全文 |
| 宣传文本 / Promotional Text | 可粘贴 `03-宣传短文.txt`，也可保留既有宣传文本 |
| App 审核信息 → 备注 / Notes | 粘贴 `02-审核备注英文.txt` 全文 |

| 审核联系信息 | 核对你自己的有效姓名、电话和邮箱 |
| 支持网址、隐私政策网址 | 沿用已发布且可正常访问的准确网址；不用本地文件路径 |
| 截图与描述 | 核对与本次版本一致，记分截图应体现【阵容】入口；不宣传尚未开放的文字直播或云同步 |

本版球队、比赛及备份保存在本机，没有广告、跟踪或额外分析 SDK。App 隐私答案应与实际分发行为一致；若 Connect 仍留有早期直播草稿的上传数据申报，先核对后更正。年龄分级等页面若提示待补，按 App 实际功能完成。工程已设置 `ITSAppUsesNonExemptEncryption = NO`，遇到额外出口合规问题时按本次实际加密功能回答，不照搬不相关 App 的答案。

此前仓库留有 Apple 的补充资料往来：若 Connect 中这些要求仍未关闭，请在同一审核对话补齐本次版本的真机演示及被要求的规则资料说明。旧的 1.5（3）录像不能标为 2.0。当前包仍含规则 PDF，所附审核备注只描述来源和阅读方式，没有声称取得分发授权，也没有声称本轮真机测试全部通过。

## 5. 提交正式审核并上线

1. 保存资料，确认构建选择正确，点击 `Add for Review / 添加以供审核`。
2. 打开本次审核提交，再点 `Submit for Review / 提交审核`。只完成第一步不会送到 Apple 审核。[Apple 提交审核步骤](https://developer.apple.com/help/app-store-connect/manage-submissions-to-app-review/submit-an-app/)
3. 如希望批准后直接上线，版本发布方式选择 **Automatically release this version / 自动发布此版本**。如希望自己控制上架时间，选择手动发布；批准后在 `Pending Developer Release` 状态点击 `Release This Version`。[Apple 发布方式](https://developer.apple.com/help/app-store-connect/manage-your-apps-availability/select-an-app-store-version-release-option/)
4. 留意审核消息；正式上线后从 App Store 核对显示版本 **2.0**，在保留旧数据的设备上更新并检查核心流程。

最后记录：最终 Build、归档日期、上传结果、提交时间及 App Store 可用状态。

## 后续版本递增约定

- 对外 Version：本次为 **2.0**；后续修复可用 **2.0.1**，功能更新可用 **2.1**。同一 App 的正式 Version 持续递增。
- 内部 Build：本次为 **1**；在同一 Version 下修改后重传时递增为 **2、3……**。新 Version 的 Build 从 1 开始，上传前核对尚未使用。
- 每次改 Version／Build 后重新 Archive，并同步 Connect 版本、归档信息和英文审核备注。原 V1.1／V1.1.1／V1.2.1 文档编号仅作历史需求标识，后续实际发布号遵循上述递增规则。
