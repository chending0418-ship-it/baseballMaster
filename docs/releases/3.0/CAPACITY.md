# 3.0 实际同步、容量与备份测量

2026-10-12，既有 `baseballmaster.cc`。使用 App 生成的完整合成比赛，普通棒球、教练投手、成人慢垒三种模式各含 146 条比赛事件；循环生成 20 场独立比赛。数据不是用户真实比赛，也不是仅健康接口或空记录。

| 测量 | 结果 |
| --- | --- |
| 单场传输样本（包含完整比赛与投影） | 约 0.82–0.85 MB JSON，gzip 约 84–87 KB |
| 20 场持久正文 | 15,458,357 字节 |
| 20 场网页投影 | 1,378,649 字节 |
| 20 场正文＋投影 | **16,837,006 字节，约 16.8 MB（16.1 MiB）** |
| 20 次完整上传确认 | 中位数约 224 ms，P95 约 631 ms |
| 30 个并发匿名历史读取 | 中位数约 341 ms，P95 约 1.48 s，最慢约 3.09 s |
| 完整记录读取样本 | 6 次，中位数约 1.70 s；包含完整正文，不能用此数代替逐球确认速度 |
| 独立备份样本 | 含两轮合成球队约 40 场的压实 DB 34.1 MB，加密压缩备份约 3.55 MB |
| 隔离恢复演练 | 恢复 DB 35.0 MB，恢复操作约 1.59 s，删除／撤销未复活 |
| 服务器剩余空间 | 本次检查约 204 GiB；现有 220 GiB 主盘，无扩容 |

**每队每月 20 场，按本次比赛样本，正式比赛正文与网页内容约 17 MB。** 加上索引、成员、审计和必要草稿，可先按每月 25–50 MB 留余量；逐球事件更多、频繁更正或未处理草稿会增大占用。未包含照片或视频，当前功能不上传这些内容。早期规划的 100–200 MB 是保守结构预算，现由完整 App 样本补充，不能将样本当作最大场次上限。

压缩备份粗略折算每队 20 场约 1.7–1.8 MB／恢复点。若同样规模保留 30 份，约 50–55 MB；这属于按**实测单份**计算的容量预算，未在一个晚上冒充已运行 30 天。历史持续增加时，每日全量快照也增长：240 场约 200 MB 正文＋投影，30 份压缩快照约 0.6 GB，仍需按实际增长校正。没有宣称跨快照去重。

结果表明目前的文字、名单和完整比赛同步可用；公网有长尾波动，前台保持最后同步时间与重试状态，不承诺所有网络即时到达。测试来自当前电脑与模拟器的网络，不等于蜂窝、微信客户端、全国节点、长期负载或套餐最大带宽验收。标称公网带宽与流量计费尚未读取账户账单，未改套餐或产生扩容操作。

原始证据：`output/validation/3.0/release-completion/full-match-sources/`、`production/acceptance.json`、`production/restore-drill.json`、`production/restart-cleanup.json`。生产 App HTTPS 另见 `native-production-02.xcresult`。验证球队均已解散并撤销访问，依 30 天恢复期自动清理；没有读取或复制其他用户比赛。
