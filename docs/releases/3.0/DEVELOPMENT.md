## 登板额度与统计 IP 分离（2026-10-11）

用户明确：局数限制按登板所在局计算，登板未投球也占一局，不能用统计 IP 的实际出局数判断额度。此前回答将两者混淆，已更正 L03／A49 的需求和实现。

当前根据已保存的逐球事件前后局面及现局面，独立汇总每个投手实际登板的局次：同一局多次重返只计一次；开赛与换边进入守备计入该局，确认换投立即计入，不等待第一球。赛前选人、进攻方提前调整投手不占用尚未登板的局；取消核对、保存失败不留下额度。统计 `PitchingLine.outsRecorded` 与 IP 不改动。撤销／恢复和历史更正从对应事件重算，沿用已有保存格式，不新增另一套易失同步的计数器。

局数提醒显示“登板 N/L 局”“最后登板局”“登板达限／超限”；投球数提醒继续独立计算。有局数限制时，换投核对与规则设置明确说明未投球也占用一局。旧档缺少开赛或完整局面记录时显示“登板待核对”，不根据 IP 补造额度。限制仍属赛事提醒，不自动换投或自动结束比赛；待确认投手时禁止记分。

## 球队共享入口与成员管理（2026-10-11）

## 比赛同步、记录交接与历史观看（2026-10-11）

用户授权继续完成这三部分。本轮在「球队 → 共享球队 → 球队比赛与历史」接入完整比赛发布、跨设备列表和详情。选定单场后才共享；本机其他比赛不上传。本机先保存，独立加密队列保留原操作与待发送内容，按变化场次压缩同步。服务端用正式修订、基础版本和记分权代次防止重复创建、旧记录覆盖、交接后双设备同时写入；比赛与网页投影同事务保存。前台定时刷新及手动刷新；后台不承诺持续同步。

**直播边界按用户最新澄清实施：原直播链接只要仍有效，任何人打开都可以看，终场后一小时也保持这一规则。主动关闭、到期或进行中一小时无同步／心跳后，原链接不再提供内容。留存档案通过独立历史入口访问，才应用永久开放、仅指定人员、不开放三种设置。** 历史权限不会提前限制直播，过期直播链接也不会自动恢复为档案链接。长期档案无一小时或七天自动清除；不开放与移除观看者均保留比赛。队内成员在 App 看历史不受网页设置影响。

## 设备配对与管理恢复（2026-10-11）

用户授权完成这两项，本轮对应 I05／I07。免注册、仅本机凭证与自有服务方案不变，不依赖 iCloud 或 Apple 账号；继续沿用「比赛／球队／统计／我的」四栏及原有记分页。

使用流程：

1. **新设备接入**：「球队 → 球队共享 → 接入这台新设备」生成 10 分钟配对二维码／链接与四词短语。原设备打开请求，选择一支球队，核对新设备、本人称呼／角色及短语后授权；新设备再确认球队和身份。两台设备归于同一成员，各持独立凭证；不默认同步其他球队，不自动交接比赛记分权。原设备的待确认配对可返回设备列表撤销。授权后新设备收起二维码，直接显示最终确认。
2. **移除设备**：「共享球队 → 球队设备与配对」；管理员可管理本队设备，其他成员仅查看和移除本人的设备。最后一台有效管理设备不能直接移除。撤销立即阻断该队访问、记分、交接及由该设备取得的浏览器授权，其他设备与其他球队关系保留。移除管理员设备或降级／移除管理员时，旧恢复卡一起失效，剩余管理员重新生成并保存。
3. **管理恢复卡**：创建球队后生成，必须明确选择已保存或稍后保存；后者持续提醒。卡片默认隐藏，主动显示后可复制或保存／分享，切到后台重新隐藏。更换恢复码后旧卡立即失效，日常成员与设备继续有效。完整恢复码仅保存在本机设备加密文件中，服务器只存摘要，不进入比赛导出或普通备份。
4. **管理权恢复**：「球队共享 → 使用恢复卡找回管理权」，粘贴恢复卡、填写称呼，先核对球队，再确认影响。恢复事务撤销该队全部旧设备、成员、未用邀请、配对、交接与观看授权，关闭旧直播和历史入口；原比赛档案保留。旧历史入口即使重新设为永久开放也不会复活。新管理员保存新卡、重新邀请成员，核对比赛后再明确接管记分。仍有可用管理员时优先重新邀请；没有有效卡不能仅凭队名或昵称恢复。

身份请求统一先加密落盘，再发送；回复丢失或确认保存失败时继续同一次操作。恢复使用的新码在提交前保存，App 重开后仍可续取同一恢复结果，不会再次创建管理员。旧设备恢复联网时，未同步比赛保留为隔离草稿；已有授权、旧码和旧链接不能恢复。此前离线副本、导出和截图不能远程收回。数据库灾难恢复、生产备份与恢复代次核对属于 R02／M03，不能把管理恢复完成等同于云端灾备完成。

## 2026-10-12 历史比赛导入

历史比赛导入已接入管理员的「球队 → 球队比赛 → 导入历史比赛」。每批选择一支本机队的 1–50 场已结束比赛，核对球员对应、自动年度及重复情况后再确认；原本机比赛独立保留，共享副本使用新编号。

已实现的行为：

- 普通比赛、教练投球、慢垒共用导入流程，保留实际时间／时区、原名单／背号、规则、逐球与纠错资料、旧文字及未知统计。年度由比赛日期推导，观赛记录继续排除在本队年度统计外。
- 同一球员 UUID 沿用原身份，同名或同背号不自动合并。管理员可明确对应到现役或停用的正式球员，未关联者独立保留并标记。对应关系随比赛同步，用于年度统计、个人比赛记录和 PDF，不重写历史快照；同一场两个人不能对应同一个身份。
- 预览不写入正式比赛。确认后先保存并读回校验完整本机备份，再逐场上传；用户可保存备份文件。取消确认不上传，暂停保留已完成场次，重开后可继续。原请求和操作编号先持久保存，服务器成功而回执丢失时重试不会再建场。
- 同来源相同内容跳过，同来源不同内容须查看云端记录核对后跳过；导入不直接覆盖、不复活已删除记录。同日同对手但不同来源只提示疑似重复，明确确认是另一场才能单独导入。同批前面的导入改变后续候选时，会暂停要求刷新预览。
