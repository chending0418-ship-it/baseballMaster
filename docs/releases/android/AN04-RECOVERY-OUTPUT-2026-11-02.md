# Android 档案恢复与报告收口（2026-11-02）

本轮在 `codex/android-migration` 实施，默认只操作合成资料和本机环境，不修改 iOS 或服务协议。

## 本机只读球队档案

新增 Room schema 5 的 `team_archives` 表，保存 SHA-256 身份和完整 `.bmteam` 原文字节。`4→5` 仅建表，既有球队、比赛、来源及操作记录保持。新导入档案直接在事务中入库，不再让文件发布和比赛事务分属两种存储。

旧 `files/team-archives` 文件保留原件。查看档案库及生成本机备份前，核验旧文件再整批迁入 Room；重复内容不重复入库，同编号不同内容拒绝。当前档案库没有删除入口；未来增加删除时须同步设计旧文件迁移完成标记或墓碑，防止旧文件重新出现。迁移失败时界面保留原文件查看／另存入口并明确警示，不删除旧文件、不显示迁移成功。备份前迁移失败则拒绝生成遗漏原件的成功备份；恢复前迁移确保旧文件存在时不会将设备视为空库。

有档案时 `.bmandroid` 使用格式 3，档案原文与球队／比赛／操作／草稿／来源在同一 Room 恢复事务提交，任意失败全部回滚。仍读取格式 1／2；没有档案时继续输出旧格式。恢复仅允许空库，授权与共享凭证不进入快照。

资源边界：最多 100 份档案、原文合计 50 MB；完整本机备份仍限制为 100 MB。50 MB 为档案原文限制，Base64 双层封装及其余比赛使完整备份超过 100 MB 时仍拒绝输出。更大的旧档案继续保留原文件与只读访问，不能假称已纳入本机备份。

新增 `TeamArchiveRecoveryTest` 覆盖档案和比赛整批恢复、提交前故障回滚、重复导入／重复恢复、损坏与冲突身份、schema 4→5 原资料保留。实际执行结果由本轮总验证记录登记，不把测试源码等同于执行通过。

## 报告与海报

逐球 PDF 局面卡片中的垒上姓名原先直接绘制，极长姓名会越过卡片边界。现测量可用宽度，超出时在卡片内提示“姓名见下方”，随后在正常文流中完整换行与分页。长守备路线采用相同策略，保留原始内容而不静默截断。

新增仪器测试生成超长中文姓名逐球 PDF、逐页 PNG 与外部文本核验清单。完整姓名仍应在最终 PDF 中存在；渲染成功本身不代表视觉核验完成。

海报预览的缓存键包含整个比赛值，使同场比赛的时间／队名更正可刷新；旧 Bitmap 在预览释放时回收，避免连续编辑保留大量 1080×1440 位图。

## 边界

本轮 `.bmteam` 仍为只读原文库，未实现档案内比赛的可编辑映射或共享授权恢复。完整 iOS 互导、所有输出范围、异常存储和厂商设备行为仍按现行计划逐项验证。正式签名、网站部署和公开 APK 分发未执行。

## 设备差异与报告视觉核验补记

API 37 实测发现旧文件库 `Files.createLink` 被 Android 应用沙箱以 `AccessDeniedException` 拒绝。现旧文件库 helper 以“暂存完整非空目录，再原子移动目录”发布内容；目录内的 `original.bmteam` 在发布前校验并同步。目录原子改名不能覆盖已有普通文件或非空档案目录，未采用先检查再复制的降级路径；不支持原子移动的文件系统明确失败。读取同时兼容历史普通 `.bmteam` 文件。当前实际 UI 仍通过 Room 库保存，仪器测试也改由 Room 入口播种、验证重复保存及取消系统另存后原文不变。

本轮 API 37 `ReportExportTest` 六项执行通过（见总验证回执）。已人工检查 `output/validation/android/2026-11-02-local/api37-full/device-files/an04-long-situation-names-page1.png` 至 `page5.png`：超长中文姓名在卡片中提示下方阅读，卡片后原文换行正常；表格跨页保留续页表头，中文及页码正常，没有卡片边界越出、内容与页脚重叠或静默截断。极端长投手姓名造成末页仅少量续行，属于完整保留内容的分页结果。另已检查现有球队统计首屏和海报，中文、标题、数值及底部说明没有明显裁切。此为具体产物的视觉检查，不代表所有 PDF／文本和设备组合已完成。
