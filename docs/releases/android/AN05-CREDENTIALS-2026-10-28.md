# AN05 设备凭证轮换与稳定加密密钥（2026-10-28，第四组）

基线 `416b645`，仅修改 Android、测试和交接。沿用现有 `/devices/credential-prepare`／`credential-commit`，不改服务／iOS，不操作生产、不发布 APK。此组完成凭证轮换机制，不代表配对／管理恢复和 AN05 已全部完成。

## 机制及失败边界

- 当前设备秘密仍是已落盘的 32 字节随机值及无填充 Base64URL。先固定独立的本机加密秘密，再保存候选新凭证和固定 rotationID；新候选没有保存成功时绝不发请求。
- 首次迁移时独立加密秘密**沿用现有设备秘密的原始 32 字节**，保存在同一 Android Keystore 密钥保护下的新 sealed 槽位。这样既有目录／比赛密文不用重写即可打开。之后认证凭证可变，加密秘密保持；普通业务备份仍不携带它。
- 优先用已保存的新凭证续取 commit；只有服务明确 `404 rotation_missing` 才用旧凭证准备同一编号／新值，再以新凭证提交。准备／提交回执丢失都重用同一候选，不能生成第二份秘密覆盖唯一恢复路径。
- 核对 commit 的 rotated=true 和原 deviceID 后，认证值、90 天维护时间及清除待轮换项在一个本机偏好提交中完成。团队成员／设备 ID 保持，旧 Bearer 在服务端退休，缓存／待发文件仍可解密。
- App 网络凭证提供器在普通请求前续取未完成轮换，并遵循当前 iOS 的 **90 天**维护周期；初次缺少日期时记录当前日期，不编造旧年龄。没有待轮换且未到期时不为了维护解密整个比赛缓存。构造客户端、启动 App 和本机记分都不发维护网络请求。
- 维护遇 409／426 时延期，普通 API 继续独立核对当前授权，不绕过恢复审查；明确 `410 rotation_expired` 才清除未提交的过期候选。未知响应、401 或网络失败不清除候选。另有显式 `rotateAndroidTeamCredential` IO 接口，须先有可核对的设备身份。
- Android SharedPreferences 的 commit 返回 false／抛异常后，内存 map 可能已经变成新值，不能将“读取到值”等同于“已落盘”。新增进程共享写失败保护：此进程内所有 CredentialVault 停止返回未确认秘密；本机普通记分仍独立，凭证流程要求重启后从持久状态续取。不会因为失败自动换账号／设备或重建凭证。

重启恢复的两种完整状态：若落盘还是旧凭证＋候选，就以候选续取原 commit；若已是新凭证且候选已清除，正常使用新值。加密秘密在两种情况下都固定。真实设备的 KeyStore 丢失／损坏仍会拒绝解密，保留文件，不能靠重新生成密钥“恢复”旧内容。

## 测试

在原回环服务新增六项：保持设备／成员身份且旧 Bearer 失效、准备回执丢失、提交回执丢失、本机最终保存失败、候选保存失败不建 transport，以及回执 deviceID 不符时保留唯一候选供核对。准备和提交均与仓库未修改的真实服务代码通信。

Android JVM 新增七项：旧目录在认证轮换后仍可解密；候选重开保持一致且不存明文；偏好提交失败／抛异常时不信任内存值；候选和最终保存失败后的保护；90 天边界及完成后的日期重置。测试注入 JDK AES 密钥，不冒充真实 Android Keystore。偏好失败注入包含“已改变内存或已写入、但返回失败”的情况，未实际填满磁盘或杀死设备进程。

首次测试编译因 Robolectric getApplication 不接受泛型参数失败，已修正；失败日志保留。最终 core 128 项、原服务集成 29 项、app 46 项，合计 **203 项，0 失败／错误／跳过**；App／AndroidTest 构建和 lint 通过，lint 0 错误、15 警告。日志为 `output/validation/android/an05-directory/credential-final.log`，冻结 XML／源码哈希在 `credential-freeze/`；复用任务不冒充重新执行。

仍未实现：产品凭证管理界面、配对／管理恢复卡流程、撤销后明确重新接入、真正设备锁屏／系统杀进程／磁盘满验证。不能将已有自动维护当作撤销后重新授权。恢复代次仍由既有阻断保护处理，未清空旧队列。接手路线见 [安卓统一交接](ANDROID-HANDOFF-2026-10-28.md)。
