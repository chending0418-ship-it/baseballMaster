# AN05 iOS 流程纠偏与固定邀请（2026-10-28，第七组）

基线 `02abe9b`。用户确认关注迁移方式后，逐项读取当前 Swift 共享流程并校正 Android 偏差，完整源码映射和缺口见 [iOS 迁移对照](IOS-PARITY-AUDIT-2026-10-28.md)。这是安卓侧适配，不改 iOS／服务／公共协议，不是新设计共享产品。

## 改动

- 共享入口与 iOS `TeamRosterView` 对齐，放在“球队”页、本机球队管理之前；点击进入时连接，去掉此前新增的独立启用步骤。启动和本机记分仍不主动连接。
- 建队显示本机来源和本次名单范围，排除已绑定来源，明确确认后发送。创建回执后提示保存管理恢复卡，默认掩码；返回从球队详情逐层回到共享列表。
- 主要邀请流程改为当前 iOS 的固定多人 member 链接，支持重新读取、二维码、系统分享／复制及明确轮换。旧单次邀请客户端仍兼容既有请求，不再作为主要产品入口。
- 新增 `FixedTeamInvitation` 与 `prepareFixedInvite`，严格 member 角色、32 字节秘密和团队 ID 校验；使用原服务的 `/team-invitation`，固定请求持久化后才发。秘密和回执仅存独立加密目录，撤权／代次变化／撤销会清理。失去响应后续取同一 operationID，不重新轮换。
- 表单在本机准备失败或服务未确认时保留输入，并可续取同一请求；完成回执保存后才退出。邀请预览与输入、编辑开始时的修订继续冻结。

二维码采用 ZXing Core 3.5.3、Apache-2.0；纯 JVM，不新增 GMS 依赖。链接使用现行固定域名及 fragment。恢复卡和邀请弹窗离开前台即隐藏；Android 实际窗口、剪贴板和分享行为尚未验证。
