# AN05 身份、目录与持久请求首批开发（2026-10-28）

基线 `b0669e5`，分支 `codex/android-migration`。用户询问并要求继续后续开发，本组启动不依赖完整比赛互导的 F10 基础。**AN04 仍未完成；开始 AN05 不代表 AN04 验收，AN05 也未完成。** 界面测试按用户要求保留后续统一进行。没有修改 iOS、共享服务实现或公共协议，没有连接生产、发布中间 APK 或正式签名。

## 实现与实际边界

- Kotlin 客户端沿用现有设备注册、球队目录、邀请预览、建队、加入、邀请和本人退出接口，路径中的 UUID 规范为小写。JSON 支持服务现行角色和可选访问／恢复版本；元数据时间用 Unix 毫秒，不与比赛内 Swift 日期混用。昵称、同名球队不作为身份键。
- 身份直接使用已存在的 Android `CredentialVault`：32 字节随机凭证、无填充 Base64URL、Bearer 和 `X-BM-Protocol: 1`。凭证必须成功本机保存后才能开连接。客户端未设置默认地址，构造不联网，App 启动及本机记分不调用协作接口。新增 INTERNET 权限是后续接入所需，不代表已有后台同步。
- OkHttp **4.12.0**（Apache-2.0；Okio 为传递依赖）使用标准 TLS 校验、独立无 Cookie／无 HTTP 缓存的客户端，拒绝所有重定向，关闭透明连接失败重试，连接／读取各 15 秒、整次 30 秒。只接受 HTTPS 的固定 `/api/v3` 基址；测试须显式启用回环 HTTP，Android 工厂不启用该选项，Manifest 继续禁止明文流量。请求和响应有限额，拒绝重复字段／坏 JSON，错误只保留稳定状态／错误码，不带服务器原始正文或凭证。
- 单笔身份操作先将原始正文、operationID、数据库恢复代次及相关球队访问代次一起保存；结果未明时禁止修改正文、换编号或新建第二笔。重试显式执行，发送前重新取球队列表核对代次；恢复代次或该队 accessEpoch 变化时保留旧请求并停止，不自动重放。响应保存失败仍保留原请求，下一次用同编号续取。本人退出后已无球队成员关系时仍允许向原接口续取终态回执，由服务校验，不恢复成员资格。
- `TeamDirectoryFile` 在 `noBackupFilesDir/team-directory` 保存单独的 AES-256-GCM 文件，使用设备凭证经 HKDF-SHA256 导出的安卓专用密钥及格式 AAD；通过 AtomicFile、显式 fsync 和落盘字节核对后才允许发送。源数据、密钥或密文损坏时拒绝读取，不初始化覆盖；写失败保留旧文件。上限 4 MiB，未知本机字段拒绝。该文件不进入 Room、`.bmandroid`、`.bmbackup`、档案或报告，生成的邀请／恢复秘密只在该加密状态中保留，不随下一笔回执被静默丢掉。
- 一个存储锁覆盖读取、落盘与发送，多个会话不能竞争覆盖同一请求。刷新成功的目录仅是缓存，不授予离线写权限；服务仍核对当前角色。没有按姓名合并、覆盖本机球队，也没有将共享名单写入现有本机数据表。

这是可直接调用并测试的基础层，**尚未接入产品共享菜单或本机／共享球队绑定**。未实现固定多人邀请、完整名单／成员管理、资料绑定与撤权清理、凭证轮换、每场比赛的加密同步队列、增量同步、交接／接管、冲突草稿、配对、恢复卡 UI 或恢复后的人工核对流程。当前恢复阻断不能在此基础层里直接解除，不提供静默丢弃旧队列的入口；这些须随后续功能接通。邀请／恢复秘密的保存不等于完整管理恢复已完成。

完整比赛的 payload、逐球／历史转换仍依赖 AN04。两个真实平台的双向记分交接与权限联调须在相关转换和 AN05 其余功能具备后执行，不能用两个 Kotlin 客户端冒充 iOS 运行结果。AN06／AN07 保持待实施／未验收。

## 非界面验证

`scripts/android/an05-local-service.mjs` 导入仓库**未修改**的 `collaboration/server.mjs`，仅启动 127.0.0.1 动态端口、内存 SQLite；不运行 `npm start`／部署脚本，不读取生产配置、环境凭证或真实数据。其标准输入只为测试注入恢复／访问代次变化，不增加服务接口。使用 Node 24.19.0，显式任务 `:core:teamServiceTest` 执行，普通 core 单测不依赖 Node。

原服务集成覆盖创建响应丢失后的同编号重试、同名独立球队、请求落盘失败不发送、服务器已提交但回执保存失败、邀请预览不入队、跨设备加入及记录员权限拒绝、管理员移除后服务端拒绝访问、恢复代次变化阻断、球队访问代次变化阻断、两个会话竞争，以及退出响应丢失后续取且不恢复授权。测试使用两个 Android/Kotlin 客户端，不声称实际 iOS 联调。

另用回环 HTTP 测试凭证获取失败不建立连接、重定向不转发授权、全局 CookieHandler 和响应 Cookie 都不使用、协议／Bearer 请求头、非规范秘密和不安全地址拒绝、坏 JSON 及错误正文不泄露。Android JVM／API31 的 AtomicFile 加密文件测试覆盖重新打开、随机 IV、密文不含明文秘密、注入提交失败保留旧文，以及错密钥／篡改后拒绝。没有 Activity、模拟器或 UI；AES 测试使用合成密钥，**不代表实际 Android Keystore／设备锁屏或断电验证**。

首次构建出现加密文件解码缺少 serializer 的编译错误，已修正，失败日志保留。最终 `:core:test` **128 项**、`:core:teamServiceTest` **7 项**、`:app:testDebugUnitTest` **36 项**，合计 **171 项，0 失败／错误／跳过**；新增 15 项为 7 项原服务集成、5 项 HTTP 保护及 3 项加密文件回归。App／AndroidTest 构建和 lint 通过，lint 0 错误、16 警告。冻结构建复用部分已通过任务，不把 UP-TO-DATE 当成重新执行。证据在 `output/validation/android/an05-directory/`，包含实际构建日志、JUnit XML、源码哈希与工具版本。真实磁盘写满、杀进程、TLS 设备环境、真实 iOS、API31／37 界面均未验证，正式生产联调和发布仍未授权。
