# 3.0.1 修复与模拟器验证

2026-10-16，分支 `codex/dev-3.0.1`，Version 3.0.1 / Build 1。本轮开发与模拟器回归已完成，生产发布状态见文末。

## 数据隔离

3.0 普通共享直接沿用本机 `StoredGame.id`，下载后 `installSharedCopy` 覆盖同一条记录并设置共享标记，因此原记录被共享权限与统计过滤接管。历史批量导入本身已生成副本编号。本轮统一使用云端比赛 ID 作为共享副本在本机的 ID，网络正文继续使用原协议编号，保证旧服务数据及其他设备兼容。

升级迁移在本机数据库单次替换中分离旧共享工作副本、恢复加密缓存保存的分享前原稿，再提交缓存迁移标记；数据库或缓存失败时阻止尚未分离的共享记录继续编辑并保留资料，本机原稿仍可独立编辑，重试不重复生成记录。原稿只能恢复设备曾保存的分享前快照，不虚构后续未保存的内容。已删除的本机原稿不会在后续同步时复活。恢复 3.0 旧备份时也重新分离旧编号，只恢复该备份涉及且设备缓存仍有的原稿，不自动上传备份中的共享修改。

首页显示本机比赛，队内列表显示共享副本；共享副本不计入本机球队统计。使用共享名单创建的本机场次也不会混入共享球队正式统计。共享源 ID 用于防重复；本机修改不会触发共享上传，成员同步、记分权、交接及冲突草稿仍限定在共享副本内。

## 其他修复

- 固定邀请由管理员获取，每队一条，可供多人使用；默认加入为成员，之后管理员调整角色。手动更换会撤销旧链接，成员不退出。旧 3.0 单次邀请接口保留。
- 新比赛选队标注本机／共享来源。比赛设置可明确选择共享目标，当前及未来比赛均先保留本机，再提供独立副本。终场页提供单场导入，记录员可操作。
- 冷启动及后台返回后按页面首次访问刷新，页面往返使用缓存，手动刷新获取最新资料；写入与正式记录同步继续运行。
- 每队最多三名管理员，按成员身份计数，沿用最后管理员保护。
- 分享卡片 Logo 沿用 2026-10-14 已部署配置；2026-10-19 用户确认微信实际分享卡片显示正常，客户端验证通过。

## 共享文案调整（2026-10-16 补充）
