入口：结果页的“逐打席速报 · 文字简版”、单打席文字简版和“全部导出并分享”。核查位置：`BaseballMaster/PlayByPlayPDFReport.swift` 的 `textPDFData`／`entries`，`BaseballMaster/ResultsViews.swift` 的 `playByPlayReport`。

- [x] **E01.1 历史归属。** 从打席／事件发生前的局面快照确定当时防守方的实际投手。每个打席显示投手姓名，建议同时保留号码；不取当前或终场投手，也不以保送／失分责任投手替代实际投球者。
- [x] **E01.2 打席中换投。** 使用按时间组织的完整事件，而非只遍历 `pa.events`。在换投生效位置显示“换投：甲 → 乙”，之后事件归属乙；换边、投手再次上场与历史补记换投均正确。
- [x] **E01.3 模式与旧数据。** 报告补齐本场规则上下文；教练投手模式明确显示“投手不适用”，不把 P 守位球员误写为实际投手。旧快照无身份时标记“未记录／待确认”，不猜测；历史球员不在当前名单中也不能漏记录。
- [x] **E01.4 布局与验证。** 全场、单打席、全部导出的简版使用同一规则。验证 PDF 文本及实际分页，长姓名与换投提示不遮挡、不截断；详细版和完整比赛记录保持一致。

验收样例：首局上投手甲／首局下投手乙；同一打席甲投一球后换丙；历史补记换投后重新导出；旧比赛缺投手快照；教练投手比赛；多页简版和单打席简版。历史换投后的姓名与事件顺序须能从 PDF 文本中核对。

## E05：首球前可多次互换攻守，首球后锁定

用户明确的是：比赛开始后、第一次实际投球前，可重复互换；首球后不可互换。核查位置：`BaseballMaster/GameStore.swift` 的开赛／投球／击球入口，`BaseballMaster/Models.swift` 的 `GameState`／`StoredGame`，`BaseballMaster/HistoryCorrection.swift` 的历史命令与回放。

实施口径：对调本场先攻／后攻，按现有模型同步主客角色；球队、球员与比赛 ID 不变，不改永久球队资料，不调用“换半局”。以下细则为实现方案，开发时与现有无投球事件及历史规则一起核对。

- [x] **E05.1 首球状态。** 增加持久化的“已记录首颗实际投球”状态，共用于界面和数据入口。不能用好坏球是否为零、计时是否开始或当前打席投球数是否为零判断，避免当前局面与首球事实混淆。
- [x] **E05.2 识别实际投球。** 逐球、直接录入击球结果、触身球及界外等现有实际投球入口统一确认首球，现有犯规投球记录按是否实际投出处理。Play Ball、开场名单调整、未实际投球罚球不应误触发首球标记；无投球故意四坏等事件须核对是否已改变开场局面，不能仅因首球标记为否就交换已有跑垒／得分／出局记录。
- [x] **E05.3 对调数据。** 将队伍、名单、打序、守备、投手、DH／二刀流、替补和球队相关状态按队伍身份完整对调；开场打者重新对应新先攻方，开场局面沿用本场现有规则。同步 `StoredGame.isHome`、结果／统计中的本队角色与赛前摘要，比分和个人记录不串队。
- [x] **E05.4 保存与回放。** 每次交换作为完整事务保存，历史命令或开场基线能正确回放；交换两次后恢复原角色。新旧存档、恢复比赛和备份兼容。首球后保持锁定：当前球数归零、换边、撤销首球、重启或历史纠错不能重新开放；锁定事实与可撤销局面分开保存。旧比赛从可靠记录迁移，已打过或无法判断的旧记录不得开放交换。
- [x] **E05.5 UI 与直播。** 开场提供清楚的互换入口与当前先攻／后攻提示，首球后隐藏或禁用并说明原因；数据入口也执行同一校验。交换后保存与直播快照一次更新，分享标题随之更新，原直播链接不变。失败时不出现只改一半的数据。
- [x] **E05.6 验证。** 普通棒球、教练投手、本队／观赛／未来安排开赛都覆盖；当前支持的名单人数、DH 与二刀流角色对调仍有效。进入调整界面、启动计时再返回，不误锁定也不绕过锁定。

验收样例：开赛后连续交换三次；仅启动计时但实际零球仍可交换；好球／坏球／击球／触身球等首球均锁定；未投出的罚球不误当实际投球；首球撤销后、恢复与纠错后仍锁定；交换两次后队伍、人员、角色、统计归属恢复一致；保存失败不部分提交；旧比赛迁移不误开放。

本项在现有数据结构上落实首球状态与身份规则，独立于 2.3 慢垒实施。不能靠改 `isTop` 或交换队名字符串完成。

## E07：统计按特定比赛多选汇总

入口：统计总览增加“比赛筛选”。保留球队、赛季和模式筛选，默认本范围全部合格比赛；可选择任意若干场。核查位置：`BaseballMaster/StatisticsViews.swift`，`BaseballMaster/Statistics.swift` 的 `seasonStatistics`，`BaseballMaster/ResultsViews.swift` 的 `GameFilterSheet`／球员详情，`BaseballMaster/StatisticsPDFReports.swift` 的 `TeamSeasonPDFReport`。

- [x] **E07.1 多选界面。** 复用／抽取已有球员比赛多选器，显示日期、对手、比分及模式，提供全选、清空、应用和取消。界面提示“已选 X／Y 场”；取消保留原范围。继续只纳入本队已结束的正式比赛，观赛、练习、未来安排与进行中比赛不计入。
- [x] **E07.2 汇总范围。** 统一按稳定比赛 ID 过滤，覆盖场数、胜负平、得失分、打击／投球／守备、排行与待确认数量。比率由选中比赛的原始累计值重算，不平均各场比率；未选比赛不得贡献任何汇总。保持普通棒球与教练投手的既有统计口径，教练投手不统计个人投手数据。
- [x] **E07.3 全选与空选。** API 区分“默认全部”和“显式空集合”，空选显示零场／无数据，不能回退到全部。切换球队／赛季／模式时刷新候选范围并默认全选；自定义选择只保留仍合格的 ID。删除／恢复比赛后交集更新，交集为空仍为空；全选状态可跟随新增合格比赛，自定义状态不擅自加选。
- [x] **E07.4 详情与导出。** 从总览进入球员详情时继承本次比赛范围，详情可在该范围内继续缩小；球队／个人统计 PDF 使用同一组比赛，列出选中场数与比赛列表。自定义报告不再写“本赛季全部比赛”；球员搜索／排序仍只影响展示，不擅自改整份报告的球员范围。
- [x] **E07.5 兼容与验证。** 现有未传比赛筛选的调用保持全部比赛语义，历史球员贡献按原规则保留。验证全选、部分、一场、空选、取消、模式切换、删除／恢复，以及页面、详情、PDF 的累计数和比率一致。

验收样例：三场比赛只选第 1 与第 3 场，页面及报告不含第 2 场；清空后保持零场；先全选再新增已结束比赛；自定义选择后新增比赛不自动加入；选中比赛恢复为进行中后移出范围；不同模式与历史球员的数据不串入。
