# 3.1.0 局面记录：按 V4 交互 demo 实现

2026-10-20。用户本轮明确：新局面记录必须沿用已做过的交互 demo。正式交互基准为 [局面记录 V4](https://baseballmaster.cc/recording/demoReview)，以 10 月 13 日补充安打守备后的最新四份源码 `website/public/recording/demoReview/` 和 [部署／验证记录](../../../website/deploy/2026-10-13-recording-v4.md) 为准。此前先观察、再进入独立守备页的原生方案已撤回，不作为本版验收。

## 两种方式

界面名称按用户最新要求为“基础版”和“Pro 版”。基础版对应原传统流程，Pro 版对应 V4 局面流程；内部枚举和旧资料兼容键保持不变。

开局设置和未来比赛的赛前规则可选“基础版／Pro 版”，默认传统记录，缺字段的旧比赛按传统打开。“练习一局”提供两种体验，重新练习保持选择，仅使用独立内存数据。传统方式保留原来的打者终点、原因、守备、跑者流程。

局面方式按 V4：

1. 第一屏六项为一垒安打、二垒安打、高飞接杀、滚地出局、守备失误、双杀。“全部击球”提供分类及搜索；另有“按击球过程记录”和“结果待确认”。
2. 在同一个球场面板选择球型、点选落点，随后自动切至同场守备／传球，依次点实际处理的人。安打也必须有处理人或显式待补；点落点不自动推断野手，更不会直接保存空垒安打。
3. 落点、传球、独立失误责任在同场切换。保留落点圈、带方向传球线和有序路线，支持单人处理未传球、接力、回传、撤回最后一人和清空路线。修改落点／球型不清空路线；连续重复点同一人不增加传球。
4. 滚地出局／双杀有常见路线快捷按钮。场内本垒打照常记录传球；越过围墙可显式选择无人处理。未看清守备或后续可显式待补，保留已知部分。
5. 有跑者或需核对的结果，进入同屏“核对本球”。点击每个人姓名展开去向、原因和附加处理；安打后进垒被触杀不改掉安打。附加跑垒处理复用同一球场，并可沿用本球路线；第三出局与回本垒同时发生时核对时序。
6. 同一球一次提交。无跑者且结果清楚时在完整球场记录完成后保存；有跑者的整球统一确认。主记分页“补充这球”重放并替换原操作，取消无影响，保存不重复投球／打席；练习也支持内存内补充。

记录球场按 V4 的 360×260 路径与色值绘制：深绿草地、土色围墙／内野、浅色边线，守备员坐标、黄色选中态、落点圈及传球箭头沿用 demo。不能复用表现页的浅绿色击球分布底图。

V4 交互球场中的守备按钮显示姓名和背号（至少 44 点高），不写守位名。路线上及直播说明仍显示专业守位与参与人姓名。球型沿用原规划中已确认的七项：地滚、强力地滚、平飞、高飞、内野小飞、触击、没有看清。正式统计由结果、实际跑者和守备裁定驱动，单独改变球型不改变统计；慢垒禁止触击。

主记分场地按用户后续反馈扩大内野，缩短本垒后留白，将大片土色场外改为较浅的草地区分，保留白色界线。姓名牌使用统一 64×32 圆角卡片，姓名优先、背号次级；守备员、垒包及慢垒第十人分别留出间距。

## 保存与历史

`BattedBallObservation` 分别保存点选／区域／未知精度、球型、主守备状态与有序路线、独立失误责任、当时参与人快照，以及每名跑者的原因／附加路线。区域只保存区域，不把中心当实测点。新方式必记球型与落点；旧资料缺失仍保持未知。

观察随本球和历史操作原子提交、撤销／重做、重启、纠错、备份及共享。更正时重放同一操作、重新捕获正确历史守备参与人；比分、球数与打席不重复。练习更正使用合成的内存检查点，不创建正式比赛，并校验草稿是否过期。

## 表现与输出

点击双方当前打者查看本场／比赛所属年度的表现及击球图。按稳定身份、比赛年度、当前比赛模式和有权查看的正式比赛汇总，共享原场次／副本去重；正在进行的打席不提前入账。统计覆盖与有去向／缺去向击球分别说明，重叠图点可以逐球查看。图上无守位名称。

直播、文字记录及现有 PDF 展示路线姓名和观察文字，完整档案保留结构化字段。已有可靠历史操作的旧路线可按当时参与身份补充直播文字，不用当前守位反推。缺证据保持未知。本版暂不新增网页／PDF 击球图或公开年度门户。
