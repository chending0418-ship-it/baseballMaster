## 用户已确认与本次修正

- 共享入口放在「球队」，保留纯本机使用方式和四栏导航。
- 固定管理员、记录员、普通成员三种角色。记录员可查看全队业务内容，与管理员一致；管理权限另按主规划矩阵控制，不能把「负责场次」误当作阅读范围。
- 对方未安装时，扫码打开邀请网页，提供 iOS App Store 下载及已安装打开入口。安装后回到原邀请继续，不承诺安装过程自动保留邀请。
- 正常记分交接由双方确认，不因超时或断线自动更换记录设备。
- 用户补充确认：进行中的实时直播保持原有开播／关闭和持链接观看方式；比赛结束后的历史回看使用三种开放权限。队内成员在 App 查看历史不受网页开放方式影响。
- 指定观看必须先授权，无授权者不能观看；状态使用普通语言，设备配对使用短语，不使用 iCloud 或 Apple 账号。
- v1 重绘的记分页不采用。比分、球场比例、投打信息和记分按钮位置沿用现有页面；共享比赛只补充简短同步提示和「同步与交接」二级入口。新增状态的位置是小范围交互建议，不重排记分界面。

## 可复现源文件

- `build-review.py`：页面内容、CSS、步骤说明及 ReportLab PDF 排版。
- `render-review.cjs`：渲染静态 HTML，原样复制现有记分页截图；不访问生产服务。
- `reference-scoring-2.3.png`：复制自 `output/releases/2.3/app-store/raw/08.png` 的现有 App 原始截图，用于防止设计稿偏离现有页面。
- 生成文件保存在 `output/samples/3.0-ui-review/`；渲染检查保存在 `output/validation/3.0/ui-review/v2/`。
- v1 的 PDF 与生成脚本保存在 `output/backups/3.0-ui-review/v1/`，仅供追溯，不作为开发基准。

使用项目已配置的 Python（ReportLab、pypdf）、Node（Playwright）和本机 Chrome，执行 `build-review.py` 可重建交付。脚本不修改 App、数据库或已有发布材料。iOS 下载使用官网现有地址 `https://apps.apple.com/cn/app/id6802063886`；静态提案中的按钮不发起下载或加入。
