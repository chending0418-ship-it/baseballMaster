# BaseballMaster V1.1.1 开发与验证记录

日期：2026-09-27。分支：`codex/v1.1.1`。状态：开发、本地自动回归及大小屏视觉验收完成；用户已明确最终以 2.0（1）合并正式发布，由本人完成签名、真机升级验收和上架。

用户本轮确认开始开发，并明确两项修正：球衣号码不参与选人逻辑；姓名号码必须直接更新队伍中的球员资料。用户要求先完成开发，发布准备在开发完成后再处理。

## 已实现

| 现场反馈 | 最终行为 |
| --- | --- |
| 首发投手被替补覆盖 | 从确认的守备阵容显式保存双方投手 ID；普通／预约／观赛／预约观赛共用相同选择逻辑。守位交换只在实际守备球员中进行。 |
| 所有队员可再次上场 | 换投、代打、代跑、守备替换及双重换人支持重返，保留退出历史和累计统计。同一打席 A → B → A 保留实际人员顺序，最终打者归属正确。 |
| 双方比赛中修改阵容 | 【阵容】保留原快捷换人，并提供双方编辑。改棒次保留当前／下一位打者及 B/S；修改守位同步投手；支持 DH／大谷条款与自动跑者。 |
| 更正姓名号码 | 直接更新对应球队名单及当前比赛，保留球员 ID、0／00、多背号、空姓名回退。名单和比赛同一事务保存，失败共同回滚，撤销／重做同步。既有事件文字保留原文，并增加更正记录。 |
| 触击界外 | 两好球时显示【触击界外出局】，记录一球、一次三振及出局；普通界外仍一键操作。教练投手不生成球员投手统计。 |
| 打者棒次 | 记分页显示“第 X 棒”，排序、换人、换边与撤销即时更新。 |
| 双方投手提醒 | 投手姓名旁显示图标和“还有 3 球／最后一局／球数达限／局数达限”等短提示；过长姓名时收为图标。当前投手无临近提示时，已达限的其他投手显示“其他达限”。点击明细含双方队名、号码、姓名、累计量／上限，达限明细在前，换边仍保留。只提醒，不强制换投。 |
| 三出局 | 明确第三出局跳过无效落垒管理；双杀／三杀保留实际出局者确认；跑垒第三出局仅选择出局者及可能得分者，必要时保留得分先后判断。 |

主记分页仍保持一屏记分；触击入口使用原底部操作行，未减少主要按钮尺寸或压缩原场地图。文字直播保持关闭。Release 忽略开发用预览启动参数。

## 回归证据

自动回归结果：**137 项单元、52 项大屏 UI、13 项小屏 UI 的最新结果均通过**。大屏含 45 项原有测试和 7 项新增测试；计数按用例去重并采用最新复跑结果。小屏含 7 项新增流程及 6 项原有／启动检查；这些是整个迭代的累计覆盖，不声称最终布局修改后重新执行了全部原有 UI。

- 最新完整单元：`final-pitcher-badge-small.xcresult` 的单元部分（137/137，无跳过）；同一包内的初次 UI 几何断言失败另行复跑关闭，未把该包整体标为成功。
- 大屏原有完整回归及本轮修复复跑：`ui-large.xcresult`、`final-large.xcresult`。首轮 49 项中的 1 项测试场景准备错误已在最终 6 项复跑中关闭。
- 小屏：`unit-and-small.xcresult`、`final-unit-small.xcresult`、`final-unit-warning.xcresult`、`final-launch-verified.xcresult`。首轮两项测试场景／标识错误均已复跑通过。
- 最终投手提示增量：`final-pitcher-badge-{small,large}-verified.xcresult` 与 `final-pitcher-badge-{small,large}-dark.xcresult` 全部通过，覆盖短提示、长姓名缩为图标、展开详情、换边、撤销、主要按钮触达及累计球数。
- Debug 与 Release 编译通过，`git diff --check` 通过；Release 编译不包含开发预览路由。
- 日志、逐项结果、截图：`output/validation/1.1.1/regression/`、`regression-results.json`。

**布局冲突已按用户决定关闭。** 发现大屏提醒横幅遮挡原“守备球队／垒上人数”标签后先暂停并询问。用户明确改为投手显示旁的小图示／短提示，现已实现。最终大小屏浅深色截图均核对；不再有顶部提醒横幅，场地图、原标签与主要按钮尺寸保留。图标的点击区域扩展 10 pt，首轮 UI 断言误把扩展的点击区域当作可见图形边界；截图确认后修正断言并复跑。深色测试最初使用了未生效的系统参数，后改用项目既有 `-appAppearance dark`，重新执行并核对真实深色截图。

- 单元测试覆盖四条开赛路径 × 主客关系 × 三组背号／名单排列；并覆盖双方选定投手与投球归属。包含替补带投手标记，号码为 10、77、00 等的变体，没有针对 10 号的分支。
- 覆盖自由换人、同一打席再次上场、DH／大谷条款、自动跑者、棒次衔接、资料同步、保存失败、撤销重做、重启、备份恢复、TXT／PDF 和赛季统计归属。
- 旧数据迁移、半局上限、终场恢复、普通／教练规则及直播关闭的原有测试继续运行。
- 大屏使用 iPhone 17 Pro，小屏使用 iPhone SE 3，均为 iOS 26.1；包含浅深色和长姓名／多背号。
- 初次测试中的测试名单无替补、按钮标识错误、打者与测试跑者重复等场景准备问题均有保留记录，修正测试场景后复跑；不删除失败用例掩盖结果。

## 代码与数据边界

新增 `LiveLineupDraft` 草稿及 `LiveLineupViews.swift`。比赛快照仅新增可选字段，旧记录可以继续读取。阵容修改后保存当时的打序，避免后续重排破坏历史局面校验。

旧比赛如果已经保存了错误投手，继续尊重该比赛明确保存的 ID 和统计；不会猜测搬移已记数据。可在阵容中显式确认实际投手，历史投球统计保留原归属。

本次姓名号码更新会同步球队名单和当前比赛；其他比赛已经保存的历史快照及逐球原文不批量重写。
