1. 2.1 问题修复、直播部署准备和发布资料在维护目录完成，验证后合入 main。
2. 在 2.2 目录合入 main 的最新提交；尚无独有开发提交时使用 `git merge --ff-only main`，开始独立开发后正常合并并回归。
3. 2.2 新功能只进入开发分支，达到对应版本发布条件后再安排合入 main，不反向混入 2.1 维护分支。
4. 已停止使用的旧本地分支清理后，其提交历史仍保留在新分支祖先链中；清理前的分支引用另有本机 Git bundle 备份，位置记录在主仓库 `.git/version-split-backup-path`。

## 本机材料与远程

`output/` 中新生成的归档、测试结果、截图和宣传材料保留在原目录，通过 `.gitignore` 排除；其中此前已经跟踪的文件继续随 Git 保存。开发／验证记录中指向未跟踪 `output/` 的链接属于本机证据，独立工作区需要时应重新生成或从原目录读取。该忽略规则不删除现有文件。

远端使用 `origin/main`、`origin/codex/release-2.1` 和 `origin/codex/dev-2.2`；本次同步保留双方提交历史，不强制推送，也不删除其他远程分支。App Store 审核和直播生产部署按上述发布安排单独执行。
