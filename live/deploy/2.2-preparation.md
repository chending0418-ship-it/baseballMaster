2026-10-03。**本地开发与测试；尚未部署 2.2 网页／服务，未归档、上传或提交审核。** 用户已确认紧凑直播设计并要求开始开发。2.1 App 已上线；历史上线记录不改写。

本版新增字段白名单、逐局开始标记、实际规则／计时、投打对决、后两位待打、历史垒况和当前阵容。保持 schema 1、单场地址、权限、数据库结构、10 秒轮询和删除规则。旧 App 缺少字段时可正常观看，缺失项显示“未记录”。App 启用后公开范围已在开播说明、关于页和官网隐私文件中说明。

## 本地交付

生成包：`output/deployments/live/2.2-2026-10-03/`。

- `release.tar.gz`：生产白名单服务及 2.2 网页，包含实际品牌图标。
- `ui-rollback.tar.gz`：同一兼容服务，搭配已发布 2.1 网页样式与脚本。新版 App 发布后需使用这种兼容回滚，不直接恢复旧白名单。
- `SHA256.json`：包及所有程序文件校验值。只含运行程序及静态资源，不包含本机比赛、发布凭证、测试数据或数据库。

本地验收：[直播 UI 验证](../../docs/releases/2.2/LIVE-UI-VALIDATION.md)。包准备不等于上线。

## 更新顺序

1. 保存现用 `current` 的目标路径及现有站点配置。只备份程序／配置，不备份 tmpfs 直播数据库。
2. 将校验后的发布包解压到独立 release 目录；继续使用原 systemd 普通运行用户、Node 24.x、`LIVE_DB` 和 127.0.0.1:18088。不要修改其他站点或开放端口。
3. 原子切换 `current`，重启直播服务，确认健康、原链接、日志及 no-store。服务进程重启保留原数据；不重启整台服务器。
4. 同步更新官网隐私政策的公开范围；这一步须在新版 App 发布之前完成。
5. 用合成比赛在正式 HTTPS 上验证 2.1 形状开播 → 同一链接递增上传 2.2 字段 → 阵容／历史／撤销 → 终场／恢复 → 关闭。使用 App 模拟器联调、WebKit 手机／小屏／桌面回归；所有临时比赛结束后主动删除。
6. 核对实际公网队名标题／OG、图标、未开始半局 `-`、开赛／用时、阵容和同步时间，保存部署记录与截图；之后再进行 App 审核发布准备。

公网服务、真实 Safari／微信客户端缓存等只能在实际执行后记录；本轮模拟器和本地 WebKit 不写成公网或真机测试。

## 回滚

尚未交付新版 App 时，可以切回原完整 release 并重启服务。已有 2.2 App 发布后，应切换到 `ui-rollback`，保留新白名单和链接升级支持，否则新快照会遭旧服务 400 拒绝。若问题仅在某个 UI 文件，也可发布修正文件并保留服务端。

回滚程序不回滚直播数据库，不恢复已关闭／过期场次。核对健康、同一个临时链接、读写权限及旧 App 形状；不同时运行多个进程。已有 2.1 维护记录见 [生产部署记录](2026-09-30-production.md)。
