# AN05 比赛读取、游标与交接队列（2026-10-28，第三组）

基线 `617c969`，继续安卓分支；不修改 iOS／服务端／协议，不运行生产，不发布中间 APK。本组是 F11 的协议和持久层，**还没有把共享比赛接入原生记分界面，也未完成 AN05**。

## 已实现

- 读取完整共享比赛 JSON、增量元数据／删除标记与参与设备。区分云端比赛 ID 和 payload 原 wire ID，不在读取时重写源比赛身份；所有未知 payload／历史字段留在 JSON 中。这里保留完整字段，不声称 HTTP 文本重新编码后逐字节相同。
- 游标仅支持固定数字 query，不允许邀请／设备秘密进入查询参数。分页中检查 cursor 前进、恢复代次、球队成员／访问代次；最终再次核对权限后才确认游标。410 cursor_expired 时从 0 重建该队缓存，未确认请求不丢弃。元数据变化时只有相同摘要可保留旧 payload，不能把新比分与旧正文拼接；删除标记移除可用正文。
- 撤权／换成员／访问代次变化时清理共享比赛和游标，保留独立未确认队列。读取时的 401／403／404 不留下该队可用比赛缓存。刷新一个队也不会重新带回本轮已失去权限的其他队缓存。
- 交接申请、接受、来源取消、管理员明确风险后强制接管。每场各有独立持久请求，包含 operationID、完整正文、成员／访问／恢复代次，不占用另一场队列。准备时重新读正式版本并与用户核对过的修订／epoch／摘要／交接状态比较；变化时重新核对，不能静默按新版本接管。
- 接受交接前先把完整 payload 保存到独立加密状态，而不只保存比分。落盘失败不发送；响应丢失或进程重开用原编号和正文续取，服务端负责幂等及当前授权。回执先持久保存并保守关闭缓存 canWrite，再用单独 GET 核对最新正式权限；旧回执不能复活已经完成的交接或旧记分权。最新 GET 失败时保留回执、权限待刷新，不假报可编辑。
- `AndroidTeamSharing` 增加比赛列表／详情、参与设备、准备／发送交接的 IO API。所有缓存和队列仍在 noBackupFilesDir 的设备绑定加密状态，未加入普通业务备份。

为容纳比赛正文，HTTP 请求／响应上限改为现行服务解压后 18 MiB；本机独立协作密文上限由首批 4 MiB 扩至 **100 MiB**。超限拒绝整次写入，保留旧文件，不丢正文生成“成功”缓存。AAD、加密算法和旧字段保持，新增字段有默认值，当前代码可读此前状态；旧代码严格解码遇新字段会拒绝而非静默丢弃。真实大文件／低内存性能仍未验证。

## 验证

原服务集成新增八项：保留 wire ID／未知历史、正常双客户端交接、接受响应丢失重试、准备落盘失败不发送与强制风险／旧版本拒绝、撤权后队列保留、过期游标重建、旧申请回执不复活交接、每场独立请求。另加完整未知 JSON／待发交接的加密重开和替换失败保护。

这些控制测试使用仓库原服务的最小合成 `match-fixture`，按现行格式 2 发布，仅核对服务控制协议和 JSON 原样保留，**不代表该最小测试文档可在真实 iOS GameStore 或安卓记分器运行**。没有用测试 fixture 接通产品发布，也不把两个 Kotlin 客户端当成真实 iOS／Android 联调。

最终 core 128 项、原服务 23 项、app 39 项，合计 **190 项，0 失败／错误／跳过**；App／AndroidTest 构建、lint 通过，0 lint 错误、16 警告。日志 `output/validation/android/an05-directory/matches-freeze.log`，冻结 XML／源码哈希在相邻 `matches-freeze/`。复用任务仍按 UP-TO-DATE 记录。
