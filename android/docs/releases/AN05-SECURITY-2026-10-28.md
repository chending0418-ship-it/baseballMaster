# AN05 配对、设备移除与管理恢复（2026-10-28，第五组）

基线 `4fab89b`，继续安卓分支。只适配已有服务和 iOS 行为，不修改公共协议、iOS 或生产。**本组是 F12 协议／持久层，不是产品安全界面或 AN05 整体验收完成。**

## 已实现

- 新设备创建 10 分钟配对请求，原设备按秘密预览选定球队的本人身份、设备标签、四词短语和成员修订；原设备明确确认后批准，新设备再核对并接受。两个设备 Bearer 不同，关联相同成员 ID，仅关联选定球队，不自动转移记分权，不复制恢复卡。
- 配对请求、秘密、状态、批准及接受的固定操作号都进入设备绑定加密存储；响应丢失按同一请求续取。读取配对状态／取消、有效设备列表及设备移除使用原接口。最后有效管理设备仍由服务保护，普通成员只能操作自己的设备。
- 本人移除设备后的终态回执可续取，但不会恢复本队成员关系；本机立即移除该队活动缓存／绑定，其他设备继续有效。未确认比赛操作仍隔离保留，不能自动重放。
- 管理恢复卡解析 `BMREC1.<teamUUID>.<canonical-secret>`，支持单份多行文本粘贴，拒绝多份、截断、非规范秘密和超长输入。秘密不出现在模型 toString、URL query、普通备份或日志。创建球队时现在保存专用恢复卡记录，也可从首批加密创建回执迁移出来，不丢掉唯一秘密。
- 管理员读取版本／是否有效、明确轮换旧卡、保存状态；旧版本迟到响应不覆盖较新卡。管理恢复先预览而不授权，再明确确认旧成员／设备、邀请、观看入口将失效；在发请求前持久保存新恢复秘密与原 operationID。
- 恢复成功后保存唯一新卡、清理该队旧缓存／绑定和配对状态。读取新目录重新取得新成员及 accessEpoch，未同步队列保留旧代次，不能覆盖正式比赛；原比赛 JSON 保持。恢复不会自动赋予新设备记分权，必须另行核对后接管。
- 过期／明确被拒绝的安全请求可在**明确确认后**归档到加密待核对记录，再重新预览／准备；这不声称旧操作从未执行（可能已经成功但后来撤权）。未知网络结果、401、数据库恢复待核对状态仍不能通过此入口清空重做。普通名单／成员的严格冲突草稿规则不变。
- `AndroidTeamSharing` 增加对应 IO API，网络仍需显式调用，未接产品菜单。既有 90 天设备凭证维护见第四组，不与管理恢复秘密或配对秘密混用。

## 验证

原回环服务新增十组：同成员双设备配对且不交接记分权、接受响应丢失重试、取消后秘密失效、最后管理设备保护及移除原设备后新设备仍有效、管理恢复撤销旧授权且保留正文、恢复响应丢失后原请求取回唯一新卡、轮换与旧创建回执迁移、配对过期后的明确归档、本机移除响应丢失后的终态续取，以及已配对设备移除后清理其接受缓存而原设备继续有效。测试 helper 仅在内存服务注入时钟前进，不等待真实 10 分钟、不改服务器实现。

另增加恢复卡输入两项纯核心测试、恢复候选／已存卡的加密重开及不含明文检查一项。使用合成凭证／JDK AES，不代表真实 Keystore、剪贴板、锁屏或实体设备验证。此组没有运行 Activity 或 UI。

最终 core 130 项、原服务 39 项、app 47 项，合计 **216 项，0 失败／错误／跳过**；App／AndroidTest 构建及 lint 通过，0 错误、15 警告。日志为 `output/validation/android/an05-directory/security-final.log`，冻结 XML／源码哈希在 `security-freeze/`。复用任务不冒充重新执行。此前各组失败／修复继续保留，不用本组结果覆盖历史未测项。
