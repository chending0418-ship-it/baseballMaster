# 棒球比赛记录大师 Android 1.0.0 发布功能计划

2026-11-09。用户指定 Android **1.0.0（Build 11）**，按交接分支 `codex/android/0.8.3-plan`（`9693b99`）启动。首批仅做 A100-01 投手限额与品牌。验收限 Android 模拟器；A100-02 至 A100-05 仍为后续工作。

- Android 对照基线为官网下载 **0.8.2（Build 10）**，打包源码 `a306b7b`。本轮核对官网入口仍指向该 APK，HEAD 返回 200。该提交至 `6540a32` 的 Android App 与 Core 主源码无差异，工程增量为共享样例路径等测试配置调整。见 [Android CURRENT](../CURRENT.md)、[0.8.2 发布计划](<0.8.2 发布功能计划.md>)。
- iOS 对照基线为 3.1.5（Build 1）合入共同 `main` 的 `6540a32`，含 `ea980a8` 的录音前同意流程。iOS 源码已合入，商店阶段按其发布计划读取。见 [PR #57](https://github.com/chending0418-ship-it/baseballMaster/pull/57)、[iOS 3.1.5 计划](<../../../ios/docs/plans/3.1.5 发布功能计划.md>)。
- 实施在 [Android 正式工作区](../../../../baseball-scorekeeper-android/) 的 `android/` 工程进行。以最新 `main` 为基线，保全该工作区已有的未提交资料。共用后台由 iOS／服务入口维护，Android 按同一协议接入。

## 实施顺序与验收

### A100-01 投手限额与品牌

- [x] `RulesForm.kt` 在新建、安排赛前配置与赛前重开处验证 3 球、全角「３」、上下界、留空和非法输入；球数与局数达限、超过时可继续正常记录。教练投手的每打席球数是赛制规则，沿用现行逻辑。
- [x] `MatchEngine.kt`／`RuleNotices.kt` 按 iOS 规则核对。明确确认登板即计入；自动沿用至下一局时，实际投球后才计新局；同局去重。测试 A 投完第一局、第二局换 B 时 A／B 各计一局，以及实际投球、非投球的跑者事件、撤销／恢复、旧数据与统计 IP 独立。历史材料不够时提示核对。
- [x] 桌面标签与 App 内品牌使用「棒球比赛记录大师」。按 [品牌 1.3](../../../../../brand/specifications/1.3/README.md) 使用既有球场 App 图标和官方轮廓字标，浅底深绿、深底反白。模拟器核对系统标签、深浅色、开屏宽版与紧凑版、设置、关于、海报与 PDF。桌面字样是否显示完整由 Launcher 版面决定。
- [ ] 发布宣传稿留到候选版本，按 [宣传规范](../../../../../brand/PROMOTIONAL-DESIGN.md) 使用 Android 实际画面与合成资料。

### A100-02 原生语音

- [ ] Android「我的 → App 设置 → 语音记分」兑换一次性开启码，复用 [独立语音服务](../../../../../modules/voice-scoring-assistant/docs/CURRENT.md) 和总 Admin。按 [iOS 原生契约](../../../BaseballMaster/VoiceScoring.swift) 实现 `/api/redeem`、`/api/entitlement`、`/api/asr-session`、`/api/asr-session/end`、`/api/analyze`。处理重试复用操作号、已用／过期码和撤权。使用 Android Keystore 保护会话凭证，保持语音权益独立；凭证、原始录音和服务密钥不得进入业务备份、APK 或日志。
- [ ] 基础和 Pro 在现场「击球进入场内」同行提供紧凑实心麦克风，语义为「语音输入」，Compose 触控区至少 48dp。每次录音前说明音频直连腾讯云语音识别、局面发往本服务，以及解析时转写和局面发往腾讯云混元 AI。用户明确同意后再请求 `RECORD_AUDIO`／签名。拒绝、取消时可直接手动记分。核对 Android 专用隐私说明及数据披露，涉及政策发布交由官网／服务工作区处理。
- [ ] 按短期签名直连 ASR，复用 iOS 16kHz 单声道 PCM 和现有协议，解析按 `hy3`／`thinking=disabled`。录音、转写、解析、确认分开；网络失败、后台／权限撤回及窗口变化时安全收尾，手动记分可继续。核对前局面、比赛 ID／修订及写权；结果过时或跑者结局不清时保留可读建议。Pro 缺落点打开原有球场编辑，最终调用现有原子记分事务，只记一次，单步撤销／恢复。
- [ ] 使用模拟器、合成语音／测试响应验证开通、取消及拒绝同意时不启动录音和上传、麦克风拒绝、撤权、转写编辑、Pro 补落点、重复确认、旧草稿、旋转与折叠。模拟响应、实际服务联调、真实麦克风分别标注证据。

### A100-03 球队固定转播源

- [ ] 从共享球队和现场记分两条入口接入 [球队固定转播协议](../../../collaboration/PROTOCOL.md#球队固定转播源)。管理员／记录员领链接、管理员换码，按同一球队码生成比分＋投手、打者、客队阵容、主队阵容四个地址。复用现有投影；共享比赛使用原始场次 ID 与当前 `writerEpoch`，切场和换码分别校验 `expectedGameID`、`expectedCode`。观察者及旧记分设备不得推送。
- [ ] 两个模拟器连接隔离服务，用实际 OBS 浏览器源验证赛前透明、首场开赛、交接、旧设备迟到包、手动切场、断线、重启后等已选场、终场及换码。四源尺寸取 [OBS 规范](../../../live/OBS.md)。旧固定码升级后提示重新确认当前场次。并行验证临时文字直播及赛后记录不受影响。
- [ ] 合并前和部署前分别核对服务能力与回执。iOS 计划记录的固定源交接／重启修复已合入源码，正式部署状态仍须以服务工作区实际回执为准。后端缺失时在 Android 显示清楚的不可用状态，保留现场手动记分。

### A100-04 名单整批提交

- [ ] 复用 `Roster.parse` 及单对话框，既有本机、对手名单支持预览、取消、整批确认。校验原始行号、空行、可选英文名、多个背号和 `0`／`00`；保持历史球员 ID，重复或同名冲突提示核对。
- [ ] 共享名单先查 `bulkRosterImport`，再调用既有 roster PATCH 的 `kind=players`，带 `baseRevision` 和持久化操作 ID。覆盖权限、预览无写入、整批原子性、丢响应重试、冲突草稿及撤权。旧服务保留原单人入口，不把批次拆成逐人请求。见 [已部署的批量接口](../../../collaboration/deploy/2026-11-04-bulk-roster-3.1.2.md)。

### A100-05 版本交付

- [ ] 从同一候选 APK 验收标准 Android 手机、平板／宽窗口与折叠模拟器。覆盖折叠／半折／展开和旋转、Pro 草稿、外接音频中断、权限、恢复后单次提交、建赛至终场、统计筛选与 PDF。用现有模拟器流程记录每组结果，按用户约定以模拟器为验收范围。共享样例取 [契约目录](../../../contracts/README.md)，区分协议对照与完整互导。
- [ ] 覆盖安装官网 0.8.2 合成数据副本，核对签名一致、原有包名、历史和队伍保留，检查新建配置以及未开启语音的旧数据。复用 Android 构建／测试入口 `scripts/android/gradle.sh`，记录源码、APK 哈希、签名、构建与检查结果。
- [ ] 记录 APK 打包、官网下载和应用市场各自状态。部署、分发、上传按实际发布授权与回执更新。实现及验证后更新本计划和 [Android CURRENT](../CURRENT.md)。
