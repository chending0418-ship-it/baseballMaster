# 棒球比赛记录大师 Android 1.0.0 发布功能计划

- 实施在 [Android 正式工作区](../../../../baseball-scorekeeper-android/) 的 `android/` 工程进行。以最新 `main` 为基线，保全该工作区已有的未提交资料。共用后台由 iOS／服务入口维护，Android 按同一协议接入。

## 实施顺序与验收

### A100-01 投手限额与品牌

- [x] `RulesForm.kt` 在新建、安排赛前配置与赛前重开处验证 3 球、全角「３」、上下界、留空和非法输入；球数与局数达限、超过时可继续正常记录。教练投手的每打席球数是赛制规则，沿用现行逻辑。
- [x] `MatchEngine.kt`／`RuleNotices.kt` 按 iOS 规则核对。明确确认登板即计入；自动沿用至下一局时，实际投球后才计新局；同局去重。测试 A 投完第一局、第二局换 B 时 A／B 各计一局，以及实际投球、非投球的跑者事件、撤销／恢复、旧数据与统计 IP 独立。历史材料不够时提示核对。
- [x] 桌面标签与 App 内品牌使用「棒球比赛记录大师」。按 [品牌 1.3](../../../../../brand/specifications/1.3/README.md) 使用既有球场 App 图标和官方轮廓字标，浅底深绿、深底反白。模拟器核对系统标签、深浅色、开屏宽版与紧凑版、设置、关于、海报与 PDF。桌面字样是否显示完整由 Launcher 版面决定。
- [ ] 发布宣传稿留到候选版本，按 [宣传规范](../../../../../brand/PROMOTIONAL-DESIGN.md) 使用 Android 实际画面与合成资料。

### A100-02 原生语音

- [x] Android「我的 → App 设置 → 语音记分」兑换一次性开启码，复用 [独立语音服务](../../../../../modules/voice-scoring-assistant/docs/CURRENT.md) 和总 Admin。按 [iOS 原生契约](../../../BaseballMaster/VoiceScoring.swift) 实现 `/api/redeem`、`/api/entitlement`、`/api/asr-session`、`/api/asr-session/end`、`/api/analyze`。处理重试复用操作号、已用／过期码和撤权。使用 Android Keystore 保护会话凭证，保持语音权益独立；凭证、原始录音和服务密钥不得进入业务备份、APK 或日志。
- [x] 基础和 Pro 在现场「击球进入场内」同行提供紧凑实心麦克风，语义为「语音输入」，Compose 触控区至少 48dp。每次录音前说明音频直连腾讯云语音识别、局面发往本服务，以及解析时转写和局面发往腾讯云混元 AI。用户明确同意后再请求 `RECORD_AUDIO`／签名。拒绝、取消时可直接手动记分。应用内「关于」已补语音数据说明；正式政策发布和商店披露留给候选版本。
- [x] 按短期签名直连 ASR，复用 iOS 16kHz 单声道 PCM 和现有协议，解析按 `hy3`／`thinking=disabled`。录音、转写、解析、确认分开；网络失败、后台／权限撤回及窗口变化时安全收尾，手动记分可继续。核对前局面、比赛 ID／修订及写权；结果过时或跑者结局不清时保留可读建议。Pro 缺落点打开原有球场编辑，最终调用现有原子记分事务，只记一次，单步撤销／恢复。
- [ ] 候选回归：麦克风拒绝、录音中断、旋转／折叠、Pro 补落点全程、过期局面与服务失败；模拟响应与实际 ASR／模型联调分别记证据。

### A100-03 球队固定转播源

- [x] 候选验收发现关联球队的本机比赛会尝试自动占用空闲转播源。已改为记录员确认场次后才发送固定转播，后续只续推仍处于当前选择的场次。转播的本机授权绑定不随业务备份恢复。

- [x] 从共享球队和现场记分两条入口接入 [球队固定转播协议](../../../collaboration/PROTOCOL.md#球队固定转播源)。管理员／记录员领链接、管理员换码，按同一球队码生成比分＋投手、打者、客队阵容、主队阵容四个地址。复用现有投影；共享比赛使用原始场次 ID 与当前 `writerEpoch`，切场和换码分别校验 `expectedGameID`、`expectedCode`。观察者及旧记分设备不得推送。
- [ ] 候选回归：浏览器源的实际渲染、断线、重启后等已选场、终场、旧固定码升级、临时文字直播与赛后记录。四源尺寸取 [OBS 规范](../../../live/OBS.md)。
- [ ] 合并前和部署前分别核对服务能力与回执。iOS 计划记录的固定源交接／重启修复已合入源码，正式部署状态仍须以服务工作区实际回执为准。后端缺失时在 Android 显示清楚的不可用状态，保留现场手动记分。

### A100-04 名单整批提交

- [x] 复用 `Roster.parse` 及单对话框，既有本机、对手名单支持预览、取消、整批确认。校验原始行号、空行、可选英文名、多个背号和 `0`／`00`；保持历史球员 ID，重复或同名冲突提示核对。
- [x] 共享名单先查 `bulkRosterImport`，再调用既有 roster PATCH 的 `kind=players`，带 `baseRevision` 和持久化操作 ID。客户端拒绝只读或已撤权角色；保存操作号及原批次，冲突可保留输入后重新预览。旧服务保留原单人入口，不把批次拆成逐人请求。见 [已部署的批量接口](../../../collaboration/deploy/2026-11-04-bulk-roster-3.1.2.md)。

### A100-05 版本交付

- [ ] 从同一候选 APK 验收标准 Android 手机、平板／宽窗口与折叠模拟器。覆盖折叠／半折／展开和旋转、Pro 草稿、外接音频中断、权限、恢复后单次提交、建赛至终场、统计筛选与 PDF。用现有模拟器流程记录每组结果，按用户约定以模拟器为验收范围。共享样例取 [契约目录](../../../contracts/README.md)，区分协议对照与完整互导。
- [ ] 覆盖安装官网 0.8.2 合成数据副本，核对签名一致、原有包名、历史和队伍保留，检查新建配置以及未开启语音的旧数据。复用 Android 构建／测试入口 `scripts/android/gradle.sh`，记录源码、APK 哈希、签名、构建与检查结果。
- [ ] 记录 APK 打包、官网下载和应用市场各自状态。部署、分发、上传按实际发布授权与回执更新。实现及验证后更新本计划和 [Android CURRENT](../CURRENT.md)。
