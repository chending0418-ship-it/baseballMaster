# 棒球比赛记录大师 Android 0.8.5 发布功能计划

2026-11-17。0.8.5 专门做 iOS 3.1.3 对照。以同一份合成名单、对阵、局次、打席和事件为输入，核对操作入口、确认步骤、保存后局面、统计和导出。版式用相近的可用宽度、方向、系统字号和主题对照；Android 保留原生返回、系统分享与折叠屏交互。

| 项目 | 基线 |
| --- | --- |
| iOS 目标 | 3.1.3 Build 5 的签名源码 `4ee4c15`；`f9566e5` 仅补验收与归档记录。Build 4 是用户已安装的 TestFlight 版，Build 5 的 Pro 四垒复用是本轮目标。参考 [3.1.3 发布功能计划](https://github.com/chending0418-ship-it/baseballMaster/blob/f9566e5279060848384417e20b9fc07f3ca61bcb/ios/docs/plans/3.1.3%20%E5%8F%91%E5%B8%83%E5%8A%9F%E8%83%BD%E8%AE%A1%E5%88%92.md)。 |
| Android 对照 | 官网 0.8.3 Build 15，签名 APK 源码 `5b02618`，状态回执 `43bf26d`。见 [0.8.3 发布功能计划](<0.8.3 发布功能计划.md>)。 |

| 版本与发行 | 0.8.5 Build 16，沿用官网包名与最低系统要求。本地开发中；覆盖签名 APK、官网更新及分发分别验收。 |

| iOS 3.1.3 项目 | Android 0.8.3 对照发现 | 0.8.5 目标与验收 |
| --- | --- | --- |
| I313-01 默认方式／赛中切换 | 新建默认基础版，记分菜单无切换入口。 | App 设置为新建、赛程预填基础或 Pro；单场仍可覆盖。非待确认的原生比赛可赛中双向切换，球数、跑者、已保存 Pro 明细及撤销／重做均保留；已存在比赛不受默认值影响。保留 iOS 来源比赛无损转换约束。 |
| I313-02 直播实际打者 | `LiveProjection` 的打者和待打队列已取当前进攻队打序；服务端旧快照修复是共享服务能力。 | 用同背号、客队第 4 棒、换人、换半局和重连复核 Android 快照；没有错队证据前不改动服务。 |
| I313-03 单次／双重换人纠错 | 能录入双重换人并重放，纠错入口缺少定位其中一组和独立更换的编辑器。 | 保存前预览原发生局次、两组球员、棒次和守位。更正一组时保留另一组及后续投球；冲突保留原记录并指出第一条待确认事件。已接入历史换人编辑器；短场景与回归结果见验证记录。 |
| I313-04 跑垒失误责任人 | 旧版仅标记待确认，跑垒失误未计球队 E，也可能把该球额外跑回的分记成自责分。 | 用当时的防守阵容选择责任人或明确待确认，选跑者与责任人共用确认页。多人因同一次失误进垒只计一次 E，事后补录不重复计数。 |
| I313-05 TB | 已计算 TB；球员详情可看，球队汇总、单场表和 PDF 不全。 | 用现有 `totalBases` 补齐。用一、二、三垒安打与本垒打各一次、另有保送和触身，期望 TB = 10。核对筛选、球队合计、单场和 PDF。 |
| I313-06 比赛分析 | 有传统比赛及统计 PDF，缺少和 3.1.3 对应的单场／球队分析流程。 | 单场、全年与筛选三种入口、生成前说明、文字与品牌 PDF。需另做完整数据范围、错误和分享验收。 |
| I313-07 主 Tab 与滚动 | 首页在重组时重算比赛列表；统计已有范围缓存，结果列表仍需大量记录时实测。 | 减少普通重组的重复排序；同一数据量验证四个主 Tab 冷开、重复切换、滚动和共享统计刷新。真实设备手感单独复核，短时模拟器场景只验证流程。 |
| I313-08 CCS 与 PB | 有 CS、PB、WP 事件；缺少捕手阻杀／传球路线、捕逸责任人及 CCS/PB 统计。 | 以当时的捕手和接球队员归属 PO、A、CCS、PB；区分 WP。接球失误、同球多人进垒、待确认、换捕手、第三出局、旧数据与相应 PDF 须一并验收。单独待实现。 |
| I313-09 跑者四垒确认 | 按跑者纵向展开，不能一眼核对整球落点。 | 同一局面比较「本球前／去向预览」，从起始垒编辑，有冲突时显示具体垒位并禁止提交。再核对紧凑手机、宽屏与辅助字号。 |
| I313-10 Pro 击球后复用 | 同样是纵向跑者列表；落点与守备已经记录在原表单。 | 需要复核时复用四垒图，保留责任、守备路线及第三出局得分判定；无须核对跑者的击球沿用快捷流程。 |

同场景核对的合成输入：首局上，0:0、0 出局、二垒有人。Pro 录入一垒安打、平飞、落点和 8→4 守备路线，预填到一、三垒。把打者改到二垒、原二垒跑者改为留垒，应禁止保存；再改为原跑者得分、打者触杀出局并沿用 8→4。预期为 1:0、1 出局、垒上无人、共 2 球。两端合成名单姓名和背号不同；规则、局面和事件一致。

0.8.3 的 360×780 dp 竖屏首屏能看到主要工具；相同记分场景压到 360×620 dp 后，跑者及判罚按钮底部被裁切。四垒编辑保留 Android 的触控与系统返回；短窗口优先显示垒况与记分动作，折叠宽屏仍需确认铰链和测量。

验收分开登记：同场景运行对照、Android 回归、官网 0.8.3 覆盖安装、候选发布。模拟器截图和日志归 `output/validation/0.8.5/`；生产服务与官网分发另行确认。
