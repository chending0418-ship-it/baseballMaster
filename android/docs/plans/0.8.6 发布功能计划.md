# Android 0.8.6 发布功能计划

2026-11-23 · 需求评估，待产品确认。来源为 [iOS 3.1.4 比赛指派与双人记录](<../../../ios/docs/plans/3.1.4 发布功能计划.md>)。[官网上一版](<0.8.5 发布功能计划.md>)为 0.8.5（Build 31）。目标版本 0.8.6，首个候选 versionCode 暂按 32 规划，构建时复核渠道占用。

| 阶段 | Android 适配与依赖 | 通过条件 |
| --- | --- | --- |
| 赛程指派 | 在球队赛程详情展示「待指派」、单人负责或阵容／局面两人。管理员选择有效成员、改派或撤销，两端使用同一套服务权限和指派修订。按球队及赛程 ID 打开同一场进行中的任务。 | iOS 指派后 Android 可见，反向操作同样成立。单人可负责整场，双人各占一岗。第三人、重复成员、非管理员指派被拒；旧客户端改期保留指派，取消和退队后入口更新。 |
| 担任阵容记录员 | Android 编辑双方本场先发、棒次、守位、姓名与背号，提交代打、代跑、换投等换人。使用稳定球员 ID 和局面位置，持久保存待处理操作及回执，显示何时生效。 | Android 提交先发及换人，iOS 局面端同场采纳；已生效的改动能在两端核对。迟到或重发有明确结果，比赛内改名不污染全队名册。 |
| 担任局面记录员 | Kotlin 本机记分引擎需接入按序应用阵容变更、去重和进程重启恢复。[现有共享比赛读取与交接](../../../android/core/src/main/kotlin/cc/baseballmaster/core/SharedMatchDirectory.kt)保留原始正文；可读取共享档案不能作为可编辑验收依据。协作依赖共享服务提供单场操作及回执，正式赛后上传仍按既有方案单列。 | iOS 管阵容、Android 记局面跑完一场，复核逐球投手、换人点、代跑得分、球员统计及终场结果。Android 双机也能开赛并完成同一套操作。 |

## 版本验收与取舍

- [ ] 验证 Build 31 原地升级后，本机比赛、球队和未指派旧赛程可用。无协作能力的服务仍可单人记分。
- [ ] 局面主设备离线继续记球；阵容端离线改动显示草稿。重连、被杀进程、改派后旧设备重试及两人同时操作，按 iOS 计划的生效位置核对规则逐项验证。
- [ ] 用同一场混合设备实录验证双方角色互换。先发、换投与下一球、代跑与得分、撤销、直播及赛后统计均以同一条已确认比赛历史为准。
- [ ] 先评估服务与本机引擎能否完成反向组合，再确定双人实录交付批次。可先交付双端赛程指派；双人实录另按联调结果排期。

当前只登记目标版本、依赖和验收条件。实现、联调、构建与官网分发均待执行。
