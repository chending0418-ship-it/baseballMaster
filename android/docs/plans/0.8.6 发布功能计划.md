# Android 0.8.6 发布功能计划

2026-11-24 · Android 0.8.6（Build 32）已完成首批开发与本地签名候选构建。赛程指派、本机补员和 Android 阵容端已验证，局面端按文末分期。来源为 [iOS 3.1.4 比赛指派与双人记录](<../../../ios/docs/plans/3.1.4 发布功能计划.md>)。[官网上一版](<0.8.5 发布功能计划.md>)为 0.8.5（Build 31）。本次候选沿用官网 0.8.x 包名和证书。

| 阶段 | Android 适配与依赖 | 通过条件 |
| --- | --- | --- |
| 赛程指派 | 在球队赛程详情展示「待指派」、单人负责或阵容／局面两人。管理员选择有效成员、改派或撤销，两端使用同一套服务权限和指派修订。按球队及赛程 ID 打开同一场进行中的任务。 | iOS 指派后 Android 可见，反向操作同样成立。未指派时仅创建本场的管理员能开赛记录、改阵容和记局面，其他管理员、记录员和成员均只读；服务端对直接写入、重试亦执行同一规则。撤销全部指派后重新核对创建人。单人可负责整场，双人各占一岗。第三人、重复成员、非管理员指派被拒；旧客户端改期保留指派，取消和退队后入口更新。 |
| 担任阵容记录员 | Android 编辑双方本场先发、棒次、守位、姓名与背号，提交代打、代跑、换投等换人。使用稳定球员 ID 和局面位置，持久保存待处理操作及回执，区分提前准备和现场执行，展示换人双方及生效位置。 | Android 提交先发及换人，iOS 局面端开赛核对一次，赛中就地显示已生效变更；已生效的改动能在两端核对。迟到或重发有明确结果，比赛内改名不污染全队名册。 |
| 担任局面记录员 | Kotlin 本机记分引擎需接入按序应用阵容变更、去重和进程重启恢复。[现有共享比赛读取与交接](../../../android/core/src/main/kotlin/cc/baseballmaster/core/SharedMatchDirectory.kt)保留原始正文；可读取共享档案不能作为可编辑验收依据。协作依赖共享服务提供单场操作及回执，正式赛后上传仍按既有方案单列。 | iOS 管阵容、Android 记局面跑完一场，复核逐球投手、换人点、代跑得分、球员统计及终场结果。Android 双机也能开赛并完成同一套操作。 |

## 赛中添加队员

在双方的[本场阵容](../../../android/app/src/main/java/cc/baseballmaster/scorekeeper/MatchLineupScreens.kt)替补区提供「添加本场队员」，空名单也可使用。单人由本场记录人办理，双人由阵容员办理。选择该队名册漏选的队员，或以姓名、背号新建本场临时队员。复用来源 ID 防止同人重复加入；临时身份及操作 ID 在重试时保持一致，同名同号需由人辨认。操作生效后两端均可从替补中选人，再按已有规则执行换人。仅加人时维持当前打席、球数、垒位及既有统计，临时队员留在本场。

## 开发顺序与完成标准

目标沿用官网 0.8.x 渠道。以下为完整目标，各项实际完成情况见文末的 Build 32 验收记录。

| 顺序 | 交付内容 | 完成标准 |
| --- | --- | --- |
| 1 · 服务协议和权限 | 在 Kotlin 核心为赛程岗位、指派代次、岗位设备、阵容草稿和应用回执建模。通过服务能力 `schedule-scoring` 识别支持情况；按球队 ID、赛程来源 ID 定位比赛。 | 旧版赛程正常读取；服务缺少岗位能力时共享场次只读。覆盖创建人、其他管理员、队内记录员、普通成员，以及一个成员的两台设备。 |
| 2 · 指派与开赛 | 在 [球队赛程页面](../../../android/app/src/main/java/cc/baseballmaster/scorekeeper/TeamScheduleScreen.kt)接入岗位详情、成员选择、开赛和进入进行中任务。由管理员按指派代次提交修改，设备领取唯一岗位后写入。 | 旧端改期保留新指派；撤销、取消、降权、两人同时打开和赛事跨过开赛时间都有确定结果。 |
| 3 · 本场增员和阵容端 | 扩展 Kotlin 本场球员集合，在阵容界面加入补选和临时登记。保留原始背号字符串及球员 ID；用本机受保护存储保存操作 ID、场次、成员和恢复代次。先持久化，再发送。 | 补员后不改变打席和垒位；联机可立即发起换人。待同步、已送达、已生效以及退回可区分。重新打开 App 不重复增员；失去资格后保留草稿供核对。 |
| 4 · 局面端和交接 | 在 [Kotlin 记分引擎](../../../android/core/src/main/kotlin/cc/baseballmaster/core/MatchEngine.kt)按当前局面校验并应用阵容变更。一次本机事务同时保存比赛和已应用操作 ID，再回传回执。改派局面员时核对完整比赛，接收成功后恢复记录。 | 换投与下一球、代跑与得分各交换一次到达顺序；撤销一球保留独立的补员或改名。旧设备不能继续提交；验收新设备上的逐球历史和责任投手。 |
| 5 · 版本候选 | 由 Android 负责 Build 31 的覆盖升级、双 Android 组合和官网候选构建，和 iOS 一起验收两种混合岗位组合。 | 用同一比赛核对记录、统计、直播及终场结果，记录各端构建号和服务提交；若双人记录未通过，按前文取舍单列可交付范围。 |

## 版本验收与取舍

- [ ] 用空替补席分别给主客队补员，覆盖名册选择、临时报名、纯本机、单人指派和双人混合设备。Android 与 iOS 互换阵容岗位，各自完成加人后代跑得分；核对稳定身份、得分归属、球队名册及历史。离线准备加人后换人，重连时依次确认，回执丢失、重启或撤权后重试不得重复生效。

- [ ] 验证 Build 31 原地升级后，本机比赛、球队和未指派旧赛程可用。纯本机比赛仍可单人记分。共享赛程无法核实创建人或服务缺少单场鉴权时只读；前者由管理员指派后再开放记录。
- [ ] 局面主设备离线继续记球；阵容端离线改动显示草稿。重连、被杀进程、改派后旧设备重试及两人同时操作，按 iOS 计划的生效位置核对规则逐项验证。
- [ ] 用同一场混合设备实录验证双方角色互换。先发、换投与下一球、代跑与得分、撤销、直播及赛后统计均以同一条已确认比赛历史为准。
- [ ] 先评估服务与本机引擎能否完成反向组合，再确定双人实录交付批次。可先交付双端赛程指派；双人实录另按联调结果排期。

## Build 32 开发与验收 · 2026-11-24

开发分支 `codex/android/0.8.6-scheduled-scorers`，已提交 [PR #77](https://github.com/chending0418-ship-it/baseballMaster/pull/77) 评审。

- **赛程指派。** 球队成员从比赛首页进入共享赛程。管理员可指派一人、将阵容与局面分给两人、改派或撤销。核对服务能力、成员资格与指派代次。旧端改期保留指派，跨过开赛时间的已指派任务保留入口。已经发布的本机赛程经 Room 写入入口检查关联，旧版发布回执会补记到比赛资料中。
- **本场替补。** 主客队可从名册补选或登记临时队员。保留来源身份及原背号，遇到同名同号需核对。测试覆盖 00 号、同一请求重试、补员前后的打者／球数／垒况／投手统计，以及下一球撤销后仍能选用新队员。本场更正在比赛内保存。
- **Android 阵容端与 iOS 局面端。** 在隔离球队服务上，Android 模拟器从实际赛程页面指派并领取阵容岗位、确认先发。iOS 3.1.4 Build 1 记保送，Android 使用本场 00 号队员替换一垒跑者；重新建立客户端会话后以同一操作 ID 重发。iOS 确认该球员跑回本垒并取得 1 分，Android 回读比分及唯一队员身份。阵容草稿存于设备加密目录，按成员、设备、恢复及指派代次核对。[Android 测试](../../../android/app/src/androidTest/java/cc/baseballmaster/scorekeeper/ScheduledLineupInteropTest.kt) · [双模拟器脚本](../../../scripts/android/verify-scheduled-lineup.py) · [Android 回执](../../../output/validation/0.8.6/mixed-yz76ih_e/android.log) · [iOS 回执](../../../output/validation/0.8.6/mixed-yz76ih_e/ios.log)
- **回归与升级。** 核心 246 项、应用 102 项、隔离服务集成 68 项通过。Android 12 模拟器用官网签名 Build 31 直接覆盖至 Release Build 32 并冷启动，逐行比对 271 支球队、156 场比赛、406 条操作和 1 份纠错草稿均一致。[测试汇总](../../../output/validation/0.8.6/unit.json) · [升级回执](../../../output/validation/0.8.6/upgrade/receipt.json)
- **本地交付。** 官网包名、Build 31 签名证书和 ZIP 对齐校验通过。[Build 32 APK](../../../output/releases/android/0.8.6/build32/BaseballMaster-Android-0.8.6-build32.apk) · [SHA-256](../../../output/releases/android/0.8.6/build32/SHA256SUMS.txt) · [微信竖图](../../../output/marketing/0.8.6/wechat/2026-11-24/Android-0.8.6-微信单页.png) · [可编辑源稿](../../../docs/design/marketing/android-0.8.6/wechat/poster.html)。官网分发仍为 Build 31。

**本次取舍。** Android 暂不领取共享赛程的局面岗位，纯本机比赛沿用单人记分。服务在交接时要求完整的正式比赛档案，包括逐球、换人、撤销与责任投手。[Android 原生历史编码器](../../../android/core/src/main/kotlin/cc/baseballmaster/core/AppleNativePitchExport.kt)和 [iOS 档案续写](../../../android/core/src/main/kotlin/cc/baseballmaster/core/AppleGameContinuation.kt)均限制可无损处理的历史类型。待覆盖双方阵容调整、撤销分支和历史交接，再开放 Android 局面端并完成反向混合组合、双 Android 实录、离线局面与终场核对。上方涉及这些组合的验收项保持待办。
