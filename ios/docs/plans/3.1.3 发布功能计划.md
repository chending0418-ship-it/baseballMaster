# 棒球比赛记录大师 3.1.3 发布功能计划

2026-11-16。iOS 3.1.3 包含五项记分与统计反馈、比赛分析，以及滚动卡顿排查。模拟器验收构建使用 3.1.3（Build 1）编译参数。版本状态见 [iOS CURRENT](../CURRENT.md)。记分、统计与滚动改动见 [草稿 PR #67](https://github.com/chending0418-ship-it/baseballMaster/pull/67)，比赛分析见 [草稿 PR #68](https://github.com/chending0418-ship-it/baseballMaster/pull/68)。

## I313-01 · 默认记分方式与赛中切换

- [x] 在「我的 → App 设置」增加「默认记录方式」，可选「基础版」或「Pro 版」，保存后用于新建比赛和安排赛程的初始选项。每场仍可单独选。已有比赛按自身设置打开，旧数据缺少设置时沿用现有基础版回退。
- [x] 在记分页的比赛操作菜单提供「记录方式」，显示当前方式并可切换。当前记分草稿完成或取消后才执行切换。在同一打席内，保存一球后即可切换，当前打者、球数、出局、垒况、比分及此前已记录的 Pro 明细须按原数据继续使用。切换保存到本场比赛，重开本场仍生效。
- [x] 验收核对新建时默认及手动覆盖、读入旧比赛、赛中双向切换、有球数的打席、撤销重做及只读保护。已有未确认草稿时比赛操作菜单保持禁用。切换沿用原比赛与直播身份。

## I313-02 · 直播显示实际进攻方的当前打者

- [x] 本机用合成比赛复现「对方打席时出现我方第一棒」。两队背号相同，第三局上半局的当前打席属于客队第 4 棒。构造带主队第 1 棒的旧形状快照后，旧观赛页显示「#12 王星野 · 第 1 棒」，应为「#12 陈昊 · 第 4 棒」。实际用户场次的触发操作仍待原始快照核对。
- [x] App 从当前进攻队的打序槽位生成打者与待打资料。观赛服务收到可以证实错队的快照时，用同局同半局的活动打席及阵容核对。资料不足时显示空位。
- [x] 验收覆盖我方分别在主场、客场，上下半局交替、跨局延续棒次、换人后当前打者更新、重连恢复。Chrome 中核对文字观赛与当前打者转播，球队固定转播接口也用错队资料验证。复现日志为 `live-batter-before.log`，修复后回归为 `live-batter-after.log`。

## I313-03 · 更正已记录的换人

- [x] 在赛中「纠正记录」里定位已经提交的单次或双重换人。显示换人发生的局、退场球员、替补、棒次和守位，允许选中错误的一组改入替补或撤掉误记的一组，保存前确认影响。使用比赛当时的名单和规则核对可换入球员。
- [x] 预览更正后的阵容、打序、垒上跑者，以及受影响的后续打席、投球、跑垒和守备记录。可重建时一起保存更正、局面和统计。遇到后续事件有冲突时，指出第一条待核对的记录并继续保留原数据，待核对后再提交。已在直播的场次用同一个链接发布修正后的局面。
- [x] 验收了两组独立事件和同一次双重换人的更正。撤掉第一组后保留第二组及后续投球，冲突时指出下一条换人且原记录保持，保存后重新打开能读取更正后的阵容。

## I313-04 · 跑垒失误指定责任人

- [x] 从「跑者」选择「守备失误造成额外进垒」时，在同一次确认里选择跑者结果和失误责任人。候选来自该事件发生时场上的防守球员，显示守位、背号和姓名。确认后写入事件和对应球员的守备失误，球队失误加一次。同一次失误导致多人推进时仍计一次。
- [x] 保留明确的「责任人待确认」选项，给已判定为守备失误但暂时不知道责任人的情况使用。先保存跑垒结果和球队的一次失误，后续在「纠正记录」补确认时更新事件和个人失误，球队失误总数保持一次。
- [x] 界面确认跑垒去向与责任人使用同一表单。原生专项覆盖两队分别守备、换人后核对资格、多人进垒、待确认后补记、撤销重做、重新打开和投手失分／自责分归属。球队 E 始终只计一次。

### 统计补列盘点

历史比赛的 TB 在读取统计时从已存安打明细计算，既有比赛文件原样保留。缺少长打分类的旧记录按现有资料计算。历史 PDF 重新导出后才会出现 TB 栏。

| 字段 | 已有资料 | 待确定的补列 |
| --- | --- | --- |
| 1B 一垒安打 | 由安打减去二垒安打、三垒安打和本垒打得出 | 单场、赛季球员／球队及 PDF 可直接显示 |
| OBP 上垒率、SLG 长打率 | 赛季球员／球队汇总及 PDF 已可显示 | 单场打击表及赛季排序可补入口 |
| CS 盗垒失败、SAC 牺牲打 | 原始计数已记录，PDF 在有事件时有文字补充 | 单场与赛季汇总及 PDF 可增加独立列 |

### 直播复现的历史依据

文字观赛页直接读取公开快照中打者和棒次的实现，至少可追溯至 2026-09-29 的 2.1 维护基线 `b814101`。本次只验证了该逻辑能显示错误资料，以及修复后的恢复行为。首次发生日期和实际场次的上游原因缺少记录。
