# 棒球比赛记录大师 3.1.3 发布功能计划

2026-11-16。iOS 3.1.3 规划稿。范围来自本次用户提出的五项现场反馈。实现、功能验证和发布均待执行，工程版本与 Build 待正式候选确定。版本状态见 [iOS CURRENT](../CURRENT.md)。计划分支 `codex/ios/3.1.3-plan` 基于 `main` 的 `8b33843`，由 [草稿 PR #67](https://github.com/chending0418-ship-it/baseballMaster/pull/67) 交付。

## I313-01 · 默认记分方式与赛中切换

- [ ] 在「我的 → App 设置」增加「默认记录方式」，可选「基础版」或「Pro 版」，保存后用于新建比赛和安排赛程的初始选项。每场仍可单独选。已有比赛按自身设置打开，旧数据缺少设置时沿用现有基础版回退。
- [ ] 在记分页的比赛操作菜单提供「记录方式」，显示当前方式并可切换。当前记分草稿完成或取消后才执行切换。在同一打席内，保存一球后即可切换，当前打者、球数、出局、垒况、比分及此前已记录的 Pro 明细须按原数据继续使用。切换保存到本场比赛，重开本场仍生效。
- [ ] 验收覆盖两种默认值、手动覆盖、读入旧比赛、赛中双向切换、同一打席已有球数、未确认草稿及有／无记分权。若当前直播正在进行，切换后观赛链接持续可用。

## I313-02 · 直播显示实际进攻方的当前打者

- [ ] 复现「对方打席时出现我方第一棒」。用主客队号码有重叠、名字不同的名单，两队提前打到不同棒次。对照 App 当前打席、发出的直播快照及页面显示，定位错误在棒次、快照还是渲染。同步核对文字观赛页和使用同一数据的当前打者转播画面。
- [ ] 以当前半局的进攻方和该队的打序为准，打者姓名、背号、棒次、待打顺序与 App 一致。进攻方打者未知时显示待确认或留空。
- [ ] 验收覆盖我方分别在主场、客场，上下半局交替、跨局延续棒次、换人后当前打者更新、重连恢复。对方第 4 棒进场时，直播显示对方第 4 棒；再次轮到我方时，恢复我方自己的打序。

## I313-03 · 更正已记录的换人

- [ ] 在赛中「纠正记录」里定位已经提交的单次或双重换人。显示换人发生的局、退场球员、替补、棒次和守位，允许选中错误的一组改入替补或撤掉误记的一组，保存前确认影响。使用比赛当时的名单和规则核对可换入球员。
- [ ] 预览更正后的阵容、打序、垒上跑者，以及受影响的后续打席、投球、跑垒和守备记录。可重建时一起保存更正、局面和统计。遇到后续事件有冲突时，指出第一条待核对的记录并继续保留原数据，待核对后再提交。已在直播的场次用同一个链接发布修正后的局面。
- [ ] 验收以 `#5 → #6`、`#7 → #8` 为例。第一组误记时可以修改或撤掉第一组，第二组照常保留。分别验证两组为独立事件和同一次双重换人，也验证发现时已发生后续投球或打席、发生后续换人冲突、取消更正和保存后重新打开。比分、球数、未受影响的事件和有更正的球员统计要逐项对照。

## I313-04 · 跑垒失误指定责任人

- [ ] 从「跑者」选择「守备失误造成额外进垒」时，在同一次确认里选择跑者结果和失误责任人。候选来自该事件发生时场上的防守球员，显示守位、背号和姓名。确认后写入事件和对应球员的守备失误，球队失误加一次。同一次失误导致多人推进时仍计一次。
- [ ] 保留明确的「责任人待确认」选项，给已判定为守备失误但暂时不知道责任人的情况使用。先保存跑垒结果和球队的一次失误，后续在「纠正记录」补确认时更新事件和个人失误，球队失误总数保持一次。
- [ ] 验收覆盖单跑者／多跑者、主客队分别守备、守备换人后选择、责任待确认后补记、撤销及重开。对照比赛过程、球队与球员 E、比分和跑垒结果，并核对涉及得分时的投手责任及自责分。

## I313-05 · 补全打击统计

- [ ] 将 TB（打击总垒数）补到统计页的球员和球队汇总、单场打击统计表及相应统计 PDF。代码已计算 `totalBases`，单场结果中的球员详情已有 TB。各处统一使用原有计算。一垒安打、二垒安打、三垒安打、本垒打分别计 1、2、3、4 个垒数。
- [ ] 逐项对照单场、球员赛季、球队赛季和 PDF 的字段，标明已有计算但漏显示的项目和缺少原始记录的项目。优先核对一垒打（1B）、上垒率（OBP）、长打率（SLG）、盗垒失败（CS）及牺牲打（SAC），形成待评审的补列清单。TB 是本版明确项，其他新增列按盘点结果确认。
- [ ] 验收以四种安打各一次为例，TB 应为 10。加入保送、触身、失误上垒或额外跑垒后 TB 仍为 10。验证跨比赛汇总、旧比赛、赛后更正以及页面与 PDF 取值一致。打击统计里的 TB 标为「打击总垒数」，与比赛进程的突破僵局记号区分。
