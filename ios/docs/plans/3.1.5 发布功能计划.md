## P1 · 固定转播源

共享球队的四条固定链接分别提供比分＋投手、当前打者、客队阵容、主队阵容。文字直播单独分享。

- [x] **交接后，新设备可用原链接继续推比分。** 共享比赛推送按服务端当前记分设备和交接代次校验，普通交接及管理员接管都可继续推送。旧设备和旧代次的迟到请求会被拒绝，四条链接沿用同一个球队码。
- [x] **重启后，固定链接等已选场次恢复。** 场次选择和被手动换下的场次写入 SQLite。快照继续保存在内存，重启后先显示透明，等已选场次同步。被换下的比赛先回传也不能抢占。
- [ ] 首次升级到修复版本时，让仍在使用旧固定源的记录员在 App 确认当前场次。旧版没有持久化选场，升级后原链接会保持透明，直到记录员选择。
- [ ] 用两个模拟器和实际 OBS 验证领源、交接、切场、重启、断线恢复及换码。确认固定链接的公开范围、常驻开播预期、停播或撤回操作，以及成员角色和旧链接持有者的访问边界。

## P1 · 语音录入

首轮实现见 [PR #53](https://github.com/chending0418-ship-it/baseballMaster/pull/53)，提交 `654e108`。

- [x] 总 Admin 已上线「语音开启码」。管理员沿用语音后台凭据，在页面手动生成、查看兑换状态、撤回未用码或设备权限。上海批次 `voice-admin-20261109T132636Z`，见 [PR #55](https://github.com/chending0418-ship-it/baseballMaster/pull/55)。
- [x] 总 Admin 生成开启码时可填发放备注，开启码状态列表在刷新、兑换后保留备注。同一批码共用一条备注。上海批次 `voice-invite-note-20261109T140210Z`，语音服务 176 项测试及桌面／窄屏浏览器验证通过。
- [x] 接入独立语音服务的现有一次性开启码。「我的 → App 设置 → 语音记分」兑换后，基础版和 Pro 的现场记分页在「击球进入场内」右侧同一行显示 56 × 44 点的实心麦克风图标按钮，辅助功能名称为「语音输入」。凭证保存在本机钥匙串，由管理员在现有服务撤回权限。
- [x] 实现单局面录音、转写、解析和人工确认。音频通过腾讯短期签名直连，转写与必要前局面使用现有服务解析。已核对的普通投球与明确的击球结果走 App 原有记分事务，支持撤销。跑者结局缺失、复杂判定或事实相互冲突时保留转写并交还手动记分。局面、修订或写权变化时旧稿不得写入。
- [x] Pro 击球建议缺少落点时提示补录，并打开原有球场。记录员可点选落点或选大致区域，核对球型、守备和跑者后再保存。
- 开发阶段使用 HY3 关闭思考。独立模块旧 60 例交付核心回放为 HY3 50/60、HY4 41/60。配对 12 例复杂题 HY3 关闭 5/12、开启 10/12，模型 p50 分别约 10 秒和 55 秒。专业放行与后续模式由独立语音项目评估。
