### 实施顺序

1. **先把 Build 1 的失败跑出来。** 同一局面保留经同意的原始音频或重录样例、标准转写、当前球数和垒况、标准判定。分别回放原音和人工修正文字，定位是录音首尾、腾讯转写、人物绑定、模型提取、记分校验还是界面操作出了问题。没有原音的截图案例以重录和人工文本建立对照，并单独标记。记录点麦到可说、停录到最终文字、解析到建议、建议到写入四段耗时和失败原因。
2. **先修音频和转写。** 检查连接前抢说、尾音、短暂停顿、段落覆盖及取消后的迟到回执。若证实抢说丢首字，在有效同意后的录音内对比明确开始提示和短时本地缓冲。以同一批音频对照现有固定热词、棒球术语及当前局面有限热词，优先覆盖一垒、二垒、安打、出局、守备位置和背号。保留原始转写。只在语境唯一时处理「2类／二垒」等同音，并允许撤回修正。同名时先用「打者」「原一垒跑者」和背号确认身份。默认使用角色和背号。若对照需要球员别名，仅在告知同意覆盖时传当前局面相关别名。测试报告不记录真实姓名、音频、鉴权信息或签名 URL。 [腾讯实时语音识别 V2](https://cloud.tencent.com/document/product/1093/131127)
3. **再修局面判断。** 把球员、起止垒、是否安全、出局和得分做成独立可核对的事实。当前局面和记分规则负责校验，模型提供口述依据。分别处理「安全上垒已经明确」和「安打、失误或野手选择仍需判定」。用中外野案例配对测试安打、传球失误、二垒封杀和缺失去向。事实齐全才提供可提交建议。只差一项时问一个具体事实，复杂或冲突时直接回手动。HY3 关闭思考作为 Build 1 基线，同样本比较规则快路径和候选模型的正确率与延迟。独立语音模块 `docs/MODEL-EVALUATION.md` 的 60 例文字回放中，HY3 关闭思考通过 50 例，仍未达到原专业门槛。正式选型使用新留出集和端到端数据。
4. **用原型把交互压到必要操作。** 已同意且麦克风可用时，试做「点麦开始 → 结束并生成建议 → 确认记入」，并提供「先看转写」支路。首次同意、接收方和数据发送时点须清楚，用户选择先看时，在主动送出前保留编辑。现有告知明确承诺点击解析后才发送转写，合并动作上线前同步告知与隐私材料。待核对时保留比分、出局和垒况，明确本球尚未记入，确认和手动接管均保持可达。 [现有语音隐私说明](../releases/3.1.5/PRIVACY-REVIEW.md) · [Apple 数据使用与分享指引](https://developer.apple.com/app-store/review/guidelines/#data-use-and-sharing)
5. **用新候选构建回归。** 先冻结样例和门槛再调参。独立语音模块验证识别与解析，iOS 使用同一个候选构建回归 iPhone、iPad 横竖屏、Duo 内外屏及折叠切换。覆盖赛前、正式记分、基础版和 Pro 练习、授权拒绝、撤权、取消、断网、迟到回执、写权交接、撤销及重复确认。增加连续两球任务，第一球弱网后转手动，下一球立刻重新语音，核对两个结果和迟到回执的归属。若共享服务改协议，先回放 Android 现有请求确认兼容。Android 界面开发单独排期。

### 拟定验收门槛

- **样本。** 首轮准备至少 60 个独立局面和约 120 段短录音，至少 30 个局面留作最后盲测。同一局面的噪声变体、同一说话人的重复录音不跨开发集和留出集。覆盖安静、风噪、场边喊声、比分播报串音、同音人名、数字垒位、否定和自我更正。安打与失误等争议判定由记录员复核。原始真人音频经同意采集并存于本地忽略目录，合成回执继续用于界面和协议回归。
- **准确与安全。** 拟定目标为留出集转写关键字段准确率 ≥95%，声明支持且事实齐全的局面正确给出建议 ≥95%。人、垒位、出局、得分及结果类别分开统计，同时报告误追问、应追问却直接建议和转手动的比例。留出集出现错人、错垒、错出局或错得分的确定建议即不通过。未经确认、重复确认、撤回后迟到和跨球写入均为零。
- **效率。** 让同一记录员用相同前局面和同一批球分别走 Build 1、手动记分与新语音，交替测试顺序。从同一局面提示开始计时，到写入本球结束，包含录音、等待、补录和改错。转手动的任务从开始累计到手动写入，未写入计失败。报告全部分配任务的分母、完成率与失败用时，语音完成率不得低于手动。单列首次授权、熟练使用及弱网结果，记录点按、耗时 p50/p90、纠错和放弃率。语音主场景以击球加跑者为主，拟定目标是中位耗时比手动少 ≥25%，p90 不慢于手动。普通投球的手动一击入口始终可用。
- **发布。** 先出 Build 1 基线报告、失败样例表和可点击流程原型，再进入客户端及模块实施。识别、记分安全和操作效率三项同时达标后，再确认新版语音是否纳入正式发布。三端交互走模拟器，识别用有标注录音回放与既有 TestFlight 自愿反馈，遵循现有不做真机验收的约定。

### 第一轮实现（2026-11-10）

- 复杂击球先展示结果和跑者去向。常见安打可在同一张卡修正原垒上跑者，使用现有记分校验，并额外拦截占同一垒或越位。转写按需展开，返回手动入口固定在顶部。
- 清晰建议从记分页到提交为四次明确点按，依次点麦、同意录音、结束并生成建议、确认记入。此前至少六次。首次系统权限另计。保留「结束，先核对转写」，数据用途与接收方在录音前显示。
- Pro 核对卡显示球型、落点和守备。字段齐全时直接确认，允许按需改球场记录。落点未知时显示「落点未记录，可补录」，照常确认，或主动打开球场补录。模型提供的守备路线须有口述证据、接传连续并与场上人员一致，方可预填。口述「三垒传一垒」且打者出局已经确认时可从原话补齐 5→3，即使解析结果漏掉传球事件也能复用已说出的路线。路线和未知落点分别保存，日后补录时仍可看到原路线。
- 腾讯识别的临时或空白回执不会覆盖已确认句段。识别中断时保留已收到的转写，需用户核对并主动解析。完整转写也只有在用户选过「结束并生成建议」后才自动开始解析。
- 第一轮验证采用合成回执和模拟器。现场口音、风噪下的转写准确率，以及复杂局面相对手动的实际用时，仍按重做计划验收。已上传的 Build 1 保留作对照。
