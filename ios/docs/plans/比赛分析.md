# iOS 比赛分析

更新：2026-11-17。归入 iOS 3.1.3，发布范围以 [3.1.3 发布功能计划](./3.1.3%20发布功能计划.md) 为准。比赛分析的实现、配置与单项回执在本文记录。iOS 与球队服务的评审分支为 `codex/ios/game-analysis`，基于 `main` 的 `8b33843`。

- 完赛结果的「比赛分析」入口覆盖已保存的单场。统计页按选定球队、年度、比赛模式和勾选场次生成全年或筛选报告。范围与统计页的数据口径一致。
- 报告包含比赛综述、关键局面或走势、各参赛球员评价和 MVP。单场可以评出双方参赛球员中的 MVP，全年及筛选分析只从本队评选。数据不足时可保留空选结果。可从报告页分享 PDF 或纯文字。
- 结果使用现有单场战报、球队年报与逐打席报告的 PDF 渲染及预览。分析采用竖版 A4，依次呈现比赛范围与数据、MVP、综述、局面和球员评价。单场球员评价按主客队分表，跨页重复表头。生成提示要求短综述、每条局面聚焦一个赛况，并区分比赛已结束与比赛过程缺失。
- 请求包含所有所选比赛的逐局比分、R/H/E、赛制、部分关键局面和球员统计。单场最多取 18 条关键事件，汇总最多取每场 3 条。旧记录缺失比赛过程时，报告依据已有比赛和统计信息。
- 点击生成前告知数据用途和处理方。请求只包含结构化比赛资料与临时球员代号，报告在 App 内恢复姓名和背号。备份、比赛备注、队名、姓名、内部 UUID 及媒体均不进入生成请求。
- App 使用球队服务的设备授权。服务端异步请求 V-API，用短请求轮询结果，避免占用长时间的代理连接。分析临时保存在服务进程内，完成约 10 分钟后清理。生成流程不落盘报告或请求正文。供应商密钥仅在球队服务受限的环境配置中，App 不持有密钥。
- 服务器接受最多 1,000 场和 200 名参赛球员，解压后的请求上限为 256 KiB。超过上限时提示缩小范围。每日默认限每台设备 5 次，服务共 60 次，单设备最多一个运行中的分析。

### 服务配置与阶段

使用同一套 Learning Center 已有的 V-API 协议。默认地址为 `https://api.vveai.com/v1`，请求 `/chat/completions`，默认模型 `gpt-5.6-luna`。在记录大师球队服务的私有部署环境中设置 `BM_GAME_ANALYSIS_VPAI_KEY`。可选环境变量为 `BM_GAME_ANALYSIS_VPAI_URL`、`BM_GAME_ANALYSIS_VPAI_MODEL` 和 `BM_GAME_ANALYSIS_DAILY_LIMIT`。缺少有效配置时功能服务关闭。

2026-11-16 使用 Learning Center 本机配置和两名虚构球员发出接口验证，V-API 返回 HTTP 401。随后使用用户提供的新凭据在本机球队服务联调，`BM_GAME_ANALYSIS_VPAI_URL` 指向 `https://api.gpt.ge/v1`，`BM_GAME_ANALYSIS_VPAI_MODEL` 为 `gpt-6.1-sol`。新接口返回 HTTP 200，结构校验通过。

2026-11-17 上海生产球队服务启用同一 V-API 地址与模型，能力接口公布 `game-analysis`。Build 2 生成页在提交前注明 V-API 处理方与发送范围。部署及验收见 [3.1.3 发布功能计划](./3.1.3%20发布功能计划.md)。公开隐私说明更新及商店发布仍待安排。

### 报告样式与品牌资产

### 本机验收

- 复用同一份全年和筛选分析重新导出 PDF，修正两份样张原有的 4 处行首标点。逐页确认文字、混排空格、品牌资产和 A4 版式。重新出稿位于 `output/validation/game-analysis/season-filtered-typography/`。

- V-API 使用 `gpt-6.1-sol` 从同一合成赛程分别生成全年 3 场和筛选 2 场的报告。iPhone 应用直接导出两份各 2 页的 A4 PDF，逐页核对品牌标志、统计范围、MVP、球员评价和中英文数字混排。样张位于 `output/validation/game-analysis/season-filtered-demo/`。

- iPhone、iPad 模拟器验证单场、全年和筛选场次的 PDF 预览及分享入口。用已生成的海浪 1–0 飞鹰分析验收两页单场报告，核对 18 名球员、跨页表头、产品标志、母品牌署名和页码。全年 3 场与筛选 2 场用模拟上游验证范围及版式。既有单场、逐打席、球队和球员四项 PDF 回归通过。截图、样张和回执在 `output/validation/game-analysis/branded-report/`。

- iPhone 17 Pro 模拟器使用新 V-API 配置生成海浪 1–0 飞鹰的合成单场报告，核对综述、关键局面、18 名球员评价、暂定 MVP 与分享入口。样例在第 1 局上半局提前结束并含一条待确认的击球，报告仅按已确认记录暂选 MVP。同步截取全年及筛选场次入口。截图与测试回执在 `output/validation/game-analysis/provider-demo/`。

- 报告改版用同一场海浪 1–0 飞鹰合成赛再次调用 `gpt-6.1-sol`。iPhone 核对首屏比分、MVP、综述与关键局面并切换到球员评价。iPad 使用深色和辅助字号核对报告阅读及菜单切换。截图与回执在 `output/validation/game-analysis/report-layout/`。
- iPhone 与 iPad 模拟器分别从比赛结果和球队统计生成 1 场单场、3 场全年及筛选后 2 场的分析。截图核对综述、关键局面、MVP、球员姓名和分享入口。iPad 上修复了场次筛选行空白处的点击响应后通过复测。
- 两项原生输入测试核对完赛与筛选口径、逐局局面、TB、球员代号和姓名留在本机。直播及球队服务共 132 项测试通过，其中包含分析权限、重复请求、结果校验和配额。布局检查 18/18。
- 本地回执位于本工作树 `output/validation/game-analysis/`。本机 UI 联调可用 `node collaboration/test/game-analysis-ui-fixture.mjs` 启动模拟上游，然后运行 `BaseballMasterUITests/testGameAnalysisGeneratesFromSingleYearAndFilteredResults`。模拟服务只监听回环地址。
