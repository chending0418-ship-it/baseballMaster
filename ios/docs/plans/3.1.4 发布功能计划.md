# iOS 3.1.4 发布功能计划

2026-11-23 · 记录员指派与双人实录方案已确认，赛中添加队员已纳入范围。待开发及跨端联调。Android 同期目标为 [0.8.6](<../../../android/docs/plans/0.8.6 发布功能计划.md>)。现有 3.1.5 候选另有安排，3.1.4 按用户指定建计划，发布先后待确认。

## 比赛指派与双人记录

球队管理员排好比赛后可以点名负责的人。一人到场能记完整场，两人到场能分担工作。按已确认方案先做赛程指派，再以一次混合设备的换人实测决定双人实录能否同版交付。

| 场景 | 建议操作与结果 |
| --- | --- |
| 赛前指派 | 在已发布的球队赛程详情点「安排记录员」，从本队有效管理员、记录员中选人。普通成员担任记录工作的需求可在评估后扩展为单场授权。指派按成员身份保存，队内可看分工，被指派人在赛程内可见自己的任务。 |
| 未指派（已确认） | 只有创建本场比赛的管理员可以开赛记录、改阵容和记局面。其他管理员、球队记录员和普通成员均只读。创建人按成员身份识别。 |
| 一人 | 指派后由该成员负责整场，两项工作均可做。指派本身不自动开赛。 |
| 两人 | 分别指定「阵容记录员」与「局面记录员」。前者维护双方当场先发、棒次、守位、姓名、背号及换人；后者记投球、打席结果、跑垒、出局、得分、局次和终场。服务按场核对人员、角色及设备，第三人和重复选同一人不能占位。 |
| 调整安排 | 管理员可改派、撤销；保留操作者及生效时间。取消赛程后关闭任务。开赛后改派须处理已提交与待处理操作，接手者看到最后确认位置，旧设备不得继续代写。退队、降权同样收回权限。 |

**第一步 · 指派（中等工作量）。** 现有赛程以球队和来源比赛 ID 标识，已有发布、改期、取消和重试去重。新增独立的管理员指派操作及修订检查。赛程发布人可以改期，但只有管理员可以改派。旧客户端改期应保留新端指派。用相同赛程身份绑定一场实际比赛，重复点开或两端同时进入都回到同一场；开赛时间过后仍能从进行中的任务进入。验收覆盖无指派、一人、两人、越权指派、跨队成员、取消、重试及双端查看。[现有赛程实现](../../../collaboration/schedules.mjs)

服务对开赛绑定、阵容和局面写入都按同一规则验权，包括旧端和重试请求。撤销全部指派时重新核对创建人身份。既有赛程允许记录员发布；若无法核实创建人为有效管理员，建议保留查看，并由管理员明确指派后再开放记录。以两名管理员、一名球队记录员和一名普通成员交叉测试，覆盖创建人独写、改派及撤销后的权限。

**第二步 · 双人实录（高工作量）。** 现行共享比赛校验当前写入设备与比赛修订，并提交整场快照。保留局面端作为唯一生成正式比赛记录的设备。阵容端在线提交有独立操作 ID 的当场变更，标明球员稳定 ID、棒位和期望的生效位置；局面端复用已有换人规则，按比赛顺序应用并回执。两端区分待处理、已生效和需核对。球员姓名／号码只修改本场显示，既有逐球及换人历史保留当时身份，全队名册另行维护。[现有比赛与交接协议](../../../collaboration/PROTOCOL.md)

双方按以下流程操作。

- 赛前由阵容员排好双方先发，点「提交先发」。局面员看到首棒、首任投手和缺项，核对一次即可开赛。
- 赛中阵容员可提前准备换人草稿，等现场宣布再点「执行换人」。两端都显示替换双方和生效位置，如「三局上，第 4 棒，下一球前换投」；局面端收到后在记分界面就地提示，无需切换页面。
- 姓名或背号订正保留原球员身份；更换上场球员走换人流程。若阵容员临时离场，由管理员将本场调整为局面员单人负责；交接时列出待处理变更，避免遗漏或重复执行。

例如两好球时换投，阵容端提交时记录当前打席及最后一球。局面未前进，局面端在下一球前应用；若下一球已经记录，两端提示核对「哪一球起由新投手投」。已记的一球保留原归属，回溯调整走纠错。换投涉及的责任投手由比赛规则计算。普通姓名修正可直接回执，只有影响当前打席、投手或垒上跑者、且时点有歧义的操作需要局面员确认。

协作通道只交换该场所需的阵容、局面位置和回执，启用双人协作时向两人说明。局面端断网可继续本机记分；阵容端离线保存草稿，恢复连接后用最新局面核对。仅在局面端持久保存操作与应用结果后显示已生效，重试及重启不重复换人。需要接管时先核对比赛数据能否在新设备恢复。正式档案保留已有赛后确认流程。

## 赛中添加队员

在主队或客队的「阵容 → 替补」提供「添加本场队员」，替补为空时也能使用。可从该队名册选择尚未列入本场的球员，或登记临时队员，按现有姓名、背号规则录入。名册球员保留来源身份，临时队员取得独立的本场 ID，只进入所选球队的本场名单。同名、同号提示核对，不能据此合并；同一名册球员只能加入同一方一次，包括已经换下的队员。

保存后列为可用替补，当前棒次、守位、垒位、球数和已有逐球记录保持原值。队员需要立即上场时，可接着点「安排换人」，沿用代打、代跑、换投或守备换人的既有规则；正式上场后才按实际参与计入统计。新增入口独立于现有的[球员资料更正](../../../BaseballMaster/LiveLineupViews.swift)，临时队员的资料调整仅作用于本场。

双人模式由阵容员添加，局面端应用成功后双方可选用；单人模式由本场唯一有记录权的人添加。草稿先生成并保存操作 ID 和队员 ID。若离线时连续准备加人和换人，先确认加人，再核对换人的生效位置；重连或回执丢失后重试，只保留一名队员和一次换人。

## 双人实录进入发布范围的条件

- [ ] 两端互换岗位，覆盖两队、空替补席、名册漏选与临时队员。三局中途补一名队员时仍能继续记球；再安排他代跑并得分，核对垒位、球员得分和逐球历史。重复提交、重启、同名同号及撤权重试均不产生重复或越权记录。

- [ ] 先跑通 iOS 记局面、Android 管阵容及反向组合，再覆盖同平台双机。双方从同一赛程进入，提交先发后，局面端首棒、首任投手及守位正确。
- [ ] 在同一打席分别测试下一球先到、换投先到，以及垒上代跑与得分同时提交。两端核对球员 ID、球数、垒位、责任投手、逐球历史和赛后统计。撤销上一球不能撤掉另一人的无关改名。
- [ ] 同一请求重试、设备重开、离线后改派和第三台设备尝试写入。只采纳仍有权限且未生效的操作一次，失败保留可核对的草稿。
- [ ] 纯本机比赛继续单人流程。共享赛程在服务端无法执行单场权限时仅供查看；拒绝旧端绕过指派写回。核对直播与统计只使用已生效阵容，终场后关闭进行中任务。

排期判断取决于两端能否各自承担局面主记录并通过以上用例。若本轮只通过第一步，版本说明只列赛程指派，双人实录仍列待验证。
