**用户确认：比赛记录纠错放在 2.1，重点解决漏记换人、漏记守位变化、漏记局面和漏记失误。** 成人慢垒、自由人、多于十人的打序及初始球数仍归 2.2。

本文件是纠错功能的最新范围，替代原《2.1 历史局面修改计划》及 review 版中相冲突的限制。**历史换人补录、历史守位补录和漏记事件插入纳入 2.1**，不再按原草案排除。以下交互、实现分期及细节为建议方案；四类重点需求已由用户确认。

## 1. 统一入口与基本流程

- [x] **C01** 比赛中和赛后都提供“纠正记录”入口，分为“漏记换人”“漏记换守位”“漏记局面”“漏记失误”。支持已经确认过的记录，不限待确认事件或最近一次操作。
- [x] **C02** 从“局次 → 主／客队打席 → 具体事件”定位错误；可选择“本事件之前／之后”。补换人不能只选一个模糊的局次，必须明确从哪次行为开始生效。
- [x] **C03** 展示当时打者、投手、守备阵容、B/S/O、比分及垒况，明确正在编辑历史；当前记分状态不随浏览变化。
- [x] **C04** 填写实际情况后“预览影响”：显示直接修改、影响时段、相关人员、比分和统计差异，以及第一个冲突。全部校验通过后一次性“保存更正”。
- [x] **C05** 可在同一草稿内继续修复受影响记录。取消不改变比赛，保存失败保留可重试草稿；正式版本更新后，旧草稿必须重新校验。

建议主流程：选择漏记类型 → 定位实际发生位置 → 补录／修改 → 预览后续影响 → 处理冲突 → 保存。

## 2. 第一重点：忘记换人

- [x] **S01** 支持补记换投、代打、代跑和守备替补：选择换下球员、换上球员及生效事件边界，显示当时可用阵容与棒次。找不到实际球员时可补全本场身份，不能用同名球员猜测或覆盖其他比赛。
- [x] **S02** 漏记换投：从确认的生效点重新归属实际投球、面对打者、出局和后续投手统计；更正前已经发生的投球仍归原投手。
- [x] **S03** 漏记代打：更正受影响打席的实际打者，保留该棒次和打席关系；打席中途代打继承当时 B/S，不把此前球数清零，也不因补换人增加一次 PA。
- [x] **S04** 漏记代跑：从指定时点替换对应垒上的实际跑者，修正之后跑垒、得分与出局记录；保留原上垒原因及投手责任链。
- [x] **S05** 漏记守备替补：修改该时点后的场上人员与该棒次替补关系，重新核对接杀、助杀和失误责任，不改全局球员姓名来冒充换人。
- [x] **S06** 以阵容时间线确定影响区间：后续相关换人、再次上场或角色变化都要重新检查，不能将剩余全场某人的名字统一替换。无法确定的归属列入草稿让记录员确认。
- [x] **S07** 覆盖打席中换投、接替时已有垒上跑者、连续换人和 A→B→A 再次上场。承接跑者的失分／自责分责任、跨投手或跨打者打席的归属按现有规则核对，不能将所有后续得分或终结结果一律划给新投手／新打者。

核心验收：第三局开头已经由 A 换为 B，却继续给 A 记了两个打席。补记换投后，生效点前 A 的记录保留，生效点后的实际投球归 B；打席、垒上跑者和责任统计不重复、不丢失。

## 3. 第二重点：忘记换位置

- [x] **F01** 支持补记历史守位变化：指定生效点，在当时场上球员之间交换或同时调整多个守位；守位调动不自动记成换人、退场或打序变化。
- [x] **F02** 每次守位调整作为一个完整操作校验，避免交换过程中暂时出现同一守位两人或同一球员两个守位。守备人数及投手／捕手要求仍按本场规则执行。
- [x] **F03** 更正后接杀、助杀、失误及传球路线使用当时阵容；若原事件按守位录入，预览实际责任人变化，若已明确指定球员则核对是否冲突，不能无条件覆盖。
- [x] **F04** 守位调动涉及投手时，除守位外还需更新有效投手及之后投球责任；涉及 DH／大谷条款时校验现有规则，不能丢掉既有身份限制。
- [x] **F05** 修改仅在相应历史区间生效；后续已有明确调位继续保留并校验。历史场图、结果页和当前守备阵容均从同一时间线生成。

核心验收：游击手和二垒手从第四局起互换，但 App 未记录；之后一条“游击手失误”应按更正后的阵容核对责任。第四局之前的记录和双方棒次保持原样。

## 4. 第三重点：局面忘记记录

- [x] **G01** 在选定事件前后补录漏掉的一球、一次击球结果、跑者进垒／得分／出局，或一个完整打席。新补录事件保存实际插入位置、更正时间与来源，不把补录时间当成比赛发生时间。
- [x] **G02** 区分“整次事件没记”与“事件已记但漏了部分结果”。例如已记安打却漏记二垒跑者得分，应补原事件中的跑者结果，不再新增一次安打、一次打席或重复的一球。
- [x] **G03** 补录后从可靠的前一状态重新计算比分、B/S/O、垒况、棒次和统计，并逐条校验后续记录；保留后续已记录的真实动作，不能重新猜默认跑垒。
- [x] **G04** 补录改变三振／保送、第三出局、换边、打席归属或比赛结束时，明确定位冲突。允许在草稿中调整受影响事件的归属与顺序，但须逐项展示并确认，不自动把所有后续记录搬到另一半局。
- [x] **G05** 为完成补漏纠错，支持有范围的撤销误录、删除重复事件、调整错误先后或归属；保留原记录及修订轨迹。不能只支持“新增一条”却无法处理由此暴露的重复／错位记录。
- [x] **G06** 只知道当前局面、记不清完整过程时，提供明确的“局面修正／过程待确认”路径：保留已知比分、球数、出局和跑者，不凭空编造安打、失误、打点或责任人。无法推导的统计标为待确认／不完整，不能宣称已准确重建。
- [x] **G07** 局面修正是可追溯的独立记录，与完整补录区分；缺失过程在后续补齐后可重新校验、消除待确认状态。已知局面仍不能包含重复跑者、超过三出局等矛盾。

核心验收：漏记跑者从二垒得分，后来又继续记录两个打席；从原发生点补上后，逐局比分、个人得分与后续垒况一致，已记录的两个打席保持。另以漏一球导致保送、漏一次第三出局、漏一个完整打席分别验收。

## 5. 第四重点：失误忘记记录

- [x] **E01** 支持将已确认的安打、野手选择或其他适用结果更正为失误，指定当时实际责任人、失误类型／次数及真实跑者去向；不能只改文字或只给球队 E 加一。
- [x] **E02** 支持“原有结果成立，同时漏记附加失误”：例如一垒安打后因传球失误多进一垒，保留有效安打，另记失误与额外进垒，不把整次结果全部改成失误上垒。
- [x] **E03** 支持单次过程涉及多次失误及不同责任人；明确各次失误造成的实际影响，团队与个人 E 合计一致，不因重复保存累计多次。
- [x] **E04** 失误责任人从该事件时点的有效阵容选择；若根源是漏记换人／换守位，可在同一草稿中先补阵容变化，再更正失误。
- [x] **E05** 联动核对 H/E、AB、打点、跑者责任、投手失分和自责分。不是所有失误都取消打点，也不能简单将失误后的所有得分改为非自责分；沿用已有记分口径及必要的人工复核。
- [x] **E06** 支持误记失误后的撤回或改回安打，验证重复更正能恢复完整原值，不重复累计打席、安打、失误或投球。

核心验收：安打漏判失误可更正；“有效安打 + 漏记传球失误”可补录；两种场景的实际进垒、比分和责任统计分别正确。

## 6. 共同基础与联动

- [x] **R01** 先盘点当前已保存的事件、前后快照、阵容和人员标识，建立四类纠错对旧比赛的支持表。不修改时重算结果应与原比分、局面和统计一致；不能只支持新比赛却宣称所有历史都可修改。
- [x] **R02** 建立明确的行为输入、换人／守位时间线、操作分组与可靠检查点；复用同一计算逻辑处理现场记分和更正草稿。第四坏球＋保送、第三好球＋三振等作为同一次实际操作处理。
- [x] **R03** 既有事件和打席 ID 尽量保留，补录事件使用新 ID；需要拆分、重归属或撤销时保存关联。展示序号可重算，仍按主客队分别累计，不能用显示编号定位原记录。
- [x] **R04** 更正预览覆盖整段后续过程：阵容、球数、棒次、跑者、换边、TB、DH、得分上限和结束决定。缺少依据时明确指出需要补充的内容，不静默跳过冲突。
- [x] **R05** 原因可从漏记类型预填，必要时补充说明；保存直接修改及自动联动差异、时间和修订号。支持撤回本次更正；已有后续操作时通过新草稿校验撤回，不能旧快照覆盖新记录。
- [x] **R06** 事件、局面、统计和修订记录原子保存，失败完整回滚；重启和备份恢复保留已提交更正。旧库迁移失败保护原数据，不清库。
- [x] **R07** 同步现场页、逐球／逐打席记录、Box Score、个人与球队统计、TXT、详细／简版逐打席 PDF 和统计 PDF。已结束比赛仍保持结束与停止计时，除非用户明确恢复比赛并通过校验。
- [x] **R08** 直播仅发布保存成功的完整修订；已关闭／过期不自动重开，不延长到期时间。重新导出读取最新更正，已分享出去的旧文件不被远程替换。
- [x] **R09** 区分旧数据的可重建、可局部更正与仅可补充说明三种能力；“过程待确认”在相关页面和导出中可见，不能显示为完整准确的统计。

## 7. 开发顺序与验收

优先顺序：**数据覆盖核查及共享计算基础 → 漏记换人 → 漏记换守位 → 漏记局面 → 漏记失误 → 全链路回归**。先完成一条“漏记换投 → 后续记录与统计归属修正 → 保存／撤回”的完整流程，再扩展其他类型；四类都属于 2.1 必须交付的重点，不因实现顺序降为可选。

| 验收组 | 场景 | 通过条件 |
| --- | --- | --- |
| A01 | 漏换投后已记录多个打席；打席中换投；已有承接跑者 | 按真实生效点分配球数与身份，原责任链保留，无重复统计 |
| A02 | 漏代打、代跑、守备替补；A→B→A | 每段实际参与人正确，棒次与当前局面一致，后续明确换人不被覆盖 |
| A03 | 两人交换／多人调整守位；含投手及 DH | 场上阵容合法，守备责任按发生时点确定，不误改棒次 |
| A04 | 漏一球、漏跑垒／得分／出局、漏一个打席 | 补入正确位置，后续逐条校验；重复或错位可在同一草稿修复 |
| A05 | 补录改变第三出局、半局、再见或终场依据 | 冲突可定位和修复，不自动移局、不强行保存、不自动恢复比赛 |
| A06 | 只有局面，过程不全 | 已知局面可追溯，未知贡献不伪造，待确认状态可见 |
| A07 | 安打改失误；有效安打附加失误；多人多次失误 | H/E、进垒、打点与责任正确，反复更正与撤回不重复累计 |
| A08 | 漏记换人／守位与漏记失误一起出现 | 同一草稿先恢复实际阵容，再更正事件责任，整份提交一致 |
| A09 | 比赛中／赛后、取消、草稿过时、保存失败、重启、备份 | 正式数据不被半份修改覆盖，历史修订及恢复结果一致 |
| A10 | 结果、赛季统计、TXT／PDF、有效／过期直播 | 同一已保存修订一致展示，范围与到期机制正确 |
| A11 | 普通棒球、教练投手、观赛、DH、TB、换人和现有撤销 | 既有规则与统计隔离保持，旧比赛能力边界有实际样本支持 |

- [x] **Q01** 每个验收组建立明确的修改前／后预期结果，分别核对个人统计、球队统计、事件数与实际投球数。
- [x] **Q02** 完成单元、集成及关键 UI 回归，模拟器大小屏检查和实际记分流程体验；失败与旧数据限制如实记录。
- [x] **Q03** 更新 2.1 发布 TODO 和功能说明；功能通过验收后，再用独立提交同步到 2.2 并完成对应回归。
