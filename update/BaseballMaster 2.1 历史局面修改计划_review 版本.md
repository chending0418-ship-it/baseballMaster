## 1. 建议的产品范围

**支持对已有历史记录进行更正，先预览后续影响，再一次性保存整场修订。已经确认过的记录也可以再次更正。**

用户从局次、打席进入具体事件，查看事件发生前后局面，再修改该事件的内容。局面、比分和统计由事件变化推导；历史修改不提供脱离事件、单独覆盖总比分或总安打数的入口。

时间范围覆盖本场第一条记录到最近一条记录，不限上一球，也不受当前 30 步内存撤销栈限制。进行中和已结束比赛使用同一套编辑、预览、校验与保存逻辑；旧记录的可编辑程度由保存的信息完整性决定。

### 1.1 修改边界

| 修改内容 | 2.1 建议范围 | 保存条件与影响 |
| --- | --- | --- |
| 备注、错字、复核说明 | 支持 | 更正说明不直接改变统计；由结构化结果生成的结果名称不能只改文字来冒充另一种判定 |
| 待确认 → 正式结果；已确认结果再次修改 | 支持 | 使用统一更正流程，保留每次原值、新值与原因 |
| 安打／失误／野手选择、安打类型、牺牲打等记分认定 | 支持 | 与实际打者和跑者去向相符；重新计算所有受影响统计，包括后续关联的责任数据 |
| 守备处理、刺杀／助杀／失误责任人 | 支持 | 责任人属于当时有效防守阵容；没有可靠历史阵容信息时，不默认套用当前阵容 |
| 一次投球的坏球、看振、挥空、界外等类型 | 有条件支持 | 重新计算 B/S、投球数及自动产生的保送／三振；若改变已记录的打席边界，必须先解决冲突 |
| 一次事件中打者和跑者的上垒、进垒、出局、得分 | 有条件支持 | 逐步验证后续事件；所有后续记录仍能合法成立才允许提交 |
| 比分、出局数、棒次与当前垒况 | 随历史事件重算 | 展示变化前后结果，不允许只改合计而留下矛盾的过程 |
| 当时的打者／投手身份、换人发生时点、历史棒次重排、DH 身份 | 本版不开放直接修改 | 会改变多个事件的参赛资格、归属或棒次；既有正常现场阵容调整入口继续使用 |
| 插入漏记事件、删除事件、调整事件先后、将打席移到其他半局 | 本版不开放 | 涉及重建比赛过程，另列后续扩展；修改导致必须执行这些操作时，本次修订不能提交 |
| 比赛双方、赛季、比赛模式、预设规则、历史计时 | 不纳入本功能 | 这些属于比赛资料或规则调整，不通过历史事件编辑改变 |

守备责任更正与换人是两种操作：前者更正该次处理记给谁，后者改变从某时起谁在场。本版支持前者，不追溯改写换人顺序。姓名、号码继续沿用现有球员资料更正流程，不借历史事件编辑修改球队名单或其他比赛。

以上“有条件支持”必须在界面明确说明原因：是后续存在可修复的冲突，还是原始资料不足，或操作超出本版范围。不能只显示笼统的“修改失败”。

### 1.2 编辑单位

- 浏览单位为“局次 → 主／客队第 N 打席 → 具体事件”，保留当前主客队分别累计、跨局连续的打席编号。
- 编辑单位为一次实际记分操作。一次投球自动产生的第四坏球与保送、第三好球与三振等作为一组重新计算，不能单独编辑自动生成的一半。
- 比赛进程中的换人、换边、TB、判罚、现场修正和结束决定也要纳入后续校验，不能只检查打席内的击球记录。
- 原始事件 ID、打席 ID 保持稳定。显示编号不作为编辑定位依据；注释和修订记录不增加一次真实打席。

## 2. 修改对后续的影响

### 2.1 三种处理结果

| 结果 | 系统处理 | 用户看到的内容 |
| --- | --- | --- |
| 仅说明变化 | 更新说明与修订记录 | “比分、局面、统计不变” |
| 变化可确定 | 根据修改点之前的可靠状态，重算后续局面、统计与展示 | 涉及的打席、人员、比分、当前局面以及统计变化 |
| 存在矛盾或缺少信息 | 保留修改草稿，暂停于第一个冲突；正式比赛不变 | 冲突的局次、打席、事件、原因和处理入口 |

历史修改遵循已记录的实际行为，不能用当时的“默认建议进垒”重新猜测后续发生了什么。比如原记录是某跑者从一垒盗二垒，不能因为前面改了跑者位置，就自动换一个人或替其决定去三垒。

用户可在同一草稿内修改受影响的后续事件，每次修改重新预览，直到整个后续过程一致。修复仍受第 1 节边界约束；需要新增、删除、跨半局搬动事件或改历史阵容时，明确提示暂不支持，允许回改或取消。2.1 不提供“忽略冲突强行保存”或“清空后续记录”按钮。

即使某一处垒况重新与原记录一致，统计影响也可能继续传播，因此不能只因局面相同就停止检查责任与统计。

### 2.2 具体例子

| 原记录 → 更正 | 预期结果 |
| --- | --- |
| 一垒安打 → 失误上垒，所有人最终去向不变 | 后续实际跑垒保留；调整 H/E、个人打击和守备统计，并复核受影响的打点、失分和自责分等统计 |
| 失误责任人由游击手 → 三垒手 | 球队失误合计不重复增加；个人失误归属从前者转给后者 |
| 看振 → 挥空，均为同一次好球且不改变打席边界 | 更新该球描述及适用分类；总投球数、好球数保持一致 |
| 原记录打者停一垒 → 实际到二垒；下一条却记该打者盗二垒 | 指出下一条的起始垒位冲突，不能直接保存 |
| 原记录安全上垒 → 出局；后面又有该球员进垒或得分 | 指出后续该跑者已不存在，需要在草稿中解决 |
| 原本第二出局 → 第三出局，但同半局还有打席 | 指出半局结束冲突；不自动将后续打席搬到下一局 |
| 修正得分，使已结束比赛的胜负发生变化 | 如结束依据仍成立，更新最终比分和赛季胜负；如再见／提前结束依据发生矛盾，必须处理终场决定 |
| 旧事件只有中文文字，缺少可以确定的动作和责任数据 | 可以查看并补充说明；不能猜出一套动作去重算整场 |

### 2.3 必须同步的结果

提交后的同一修订统一驱动：逐球文字、逐打席记录、逐局比分与 R/H/E、B/S/O、垒况、当前投打及棒次、球数提醒、打击／投手／守备 Box Score、个人逐场记录、球队／球员赛季汇总、TXT、两种逐打席 PDF 和其他统计 PDF。

进行中比赛继续沿用不计入正式赛季汇总的现有口径。已结束的本队比赛更新赛季汇总；观赛和练习仍按现有规则排除。统计按修订后的比赛数据重新汇总，避免把一次更正重复累加成两场或两次贡献。

打点、自责分、第三出局计分、TB 自动跑者与换投前后责任必须有独立验收样例。不是把当条事件的安打数加减一下就完成。资料或责任计算能力不足时，明确限制该项编辑；不扩大自动计算承诺，也不在本功能中悄悄变更全 App 的记分口径。

已导出到“文件”或已经分享出去的 TXT／PDF 不会被远程替换。App 内重新导出使用最新修订，并展示最后更正时间，帮助区分旧报告。

## 3. 比赛中与赛后的使用流程

### 3.1 比赛中

入口沿用比赛记录页，并从现场记分提供清晰的“历史记录”访问路径，维持现有一屏记分布局。

1. 选择局次／打席，查看事件前后比分、B/S/O、投打及垒况，页面明确显示“正在查看历史”。
2. 点击事件的“修改记录”，按事件类型显示可编辑项，并填写更正原因。
3. 点击“预览影响”，列出直接修改、自动联动变化及需处理的冲突。
4. 冲突可在同一草稿中逐条处理；全部通过后，显示整场影响摘要。
5. 点击“保存更正”，整体保存成功后返回当前比赛；失败保留草稿并说明原因。

查看和编辑历史不自动暂停比赛计时。编辑期间使用独立页面，保存或取消后回到现场继续记分；不把历史快照写进当前正式局面。草稿若因其他操作而落后于正式比赛修订，必须重新预览，不能覆盖更新后的比赛。

2.1 首版不要求跨重启恢复未提交草稿。App 被关闭时只保留已提交版本，重新打开要明确没有保存未提交的修改；已提交更正和修订历史必须跨重启保留。

### 3.2 比赛结束后

- 从“历史比赛 → 比赛结果 → 记录”直接修改，不要求先点“恢复为进行中”。
- 一般更正保留已结束状态、实际结束时间和有效的结束原因，计时保持停止。
- 若改变得分／出局后，原结束依据不再成立，预览必须单独提示。用户可纠正为真实的结束原因；若确实还要继续比赛，则走现有“恢复为进行中”操作。不能自动补打一局、自动改变结束原因或自动恢复比赛。
- 恢复比赛属于独立明确操作；在相关更正能够形成合法状态以前，不先提交半套历史修改。因更正需要插入／删除比赛过程的情况，依第 1 节暂不开放。
- 本地更正不设“终场后一小时”的编辑限制，只要该场比赛仍保存在本机即可。
